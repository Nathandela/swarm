swarm · the drawing the code cites

The conversation surface, component by component.

Every element the phone will draw, in each state it can be in, with the exact words it says. Nothing here is decoration. The build gate is bidirectional over the derivation record — a kit component cannot exist without a row in docs/design/substrate-components.md, and a row cannot outlive its component. Copy is byte-checked against this sheet, in part — scripts/check-conversation-copy.py, gated in internal/verify/conversation_copy_test.go, compares the rows whose screens are built the rows whose screens are built today) in one direction, and prints that ratio on every run so a green result is never mistaken for the whole sheet.

The flow argument, the audit committee's findings, and the rulings that produced this drawing are in the flow document. This is the part you sign.

01 · the whole

One screen, three regions, nothing else

A fixed header. A message list that is the only thing that scrolls. A composer that stays above the keyboard. The connection strip survives above all three — it is the only warning the app has, and this is the one screen where you are typing.

Three structural rules, and they are the reason for the whole slice

Only the list scrolls. Today one scroll wraps the entire page, so the notices, the conversation and the controls move as one document. That is what made your screen take two screenshots.

The tab bar goes; the connection strip stays. The strip lives above the destination for a recorded reason — a warning that belongs to one screen is a warning the others do not have. Dropping it here would make the screen where you type the only screen that cannot tell you the link is down.

The composer never scrolls away. It pins above the keyboard. Today it is the last child of the page, below the whole transcript and below three buttons.

03 · the words

Every string, exactly

These are the strings, and anything not on this sheet does not belong on the screen. A row bound to a source file is compared byte for byte, and the checker prints each sentence's non-ASCII codepoints, because the failure mode is the near-miss: an en dash for an em dash renders identically and is not the same string. A row not yet bound to a file is reviewed rather than checked — tabled copy for a screen nobody has built yet is legitimate, and the binding is added when the screen is.

What it does not do, stated because the claim above depends on it. It asks whether a tabled sentence appears in the file that must carry it. It does not ask whether every string on those screens is on this sheet — the direction that catches a sixth wording being added tomorrow, and the direction that would have passed all four of this tree's rival stale-turn sentences, because one of them was right. That half wants a literal sweep with an allowlist, and it is real work rather than a widening. It is tracked, not pretended.

This sheet claimed such a gate before it had one, and the claim was empty: a sentence shipped in the composer that appears on no row here, and nothing failed. It was retracted, and then the gate was built — which is the better repair. The sheet now says something true because the check exists, rather than something weaker so that it could be true.

04 · the rules that are not visual

What the drawing also decides

  • Stick to the bottom only if you were already there. Scrolled up, new messages land below without moving you. Never while a decision is unanswered.
  • Loading earlier preserves your place. Prepending history keeps the item you were reading under your thumb.
  • A collapsed card stays collapsed and an open one stays open, across incremental updates and across a rebuild.
  • Every target is at least 48 dp. The reference client ships 32 to 34 and is below every published minimum; error rates roughly treble under 44.
  • Every privileged control filters obscured touches, as they do today. Send is a privileged control.
  • The decision announces itself to a screen reader when it arrives, and reads in order with the message it belongs to.
  • Nothing is queued on the phone. Input is live-only; a message that cannot go is refused visibly and kept in the field.
  • The list holds up to 200 live and 200 backfilled items with no recycling today. The new layout is measured for jank and memory before it is called done.

05 · the other end

What the terminal draws, and what it may not

Nothing is switched on. Two repairs, and one refusal.

▸ claude-NewLatexCV        claude  working     ~/Code/swarm         phone sent 09:41
  codex-swarm-relay        codex   needs you   ~/Code/swarm
  claude-soml-ia           claude  idle        ~/Code/soml-ia
claude-NewLatexCV   ctrl+q returns to swarm       phone sent 2 messages · 09:41
  • phone control becomes phone sent HH:mm. The old marker was driven by the lease this wave deletes. The new one reports the fact we actually have: this phone sent, recently.
  • took over from phone is deleted, not reworded. It claims an eviction that was disproved — both streams survive, in both orders — and it is sampled once before dialling, so it could not be true later even if it were true then.
  • It is not phone is here. That is a presence claim, and presence needs begin, renew and end, an expiry, session binding, cleanup on transport loss and aggregation across devices. None of it exists. We do not name a fact we do not have.
  • Nothing is written into the terminal's own output. No prefix, no colour, no marker on the line: prefixing changes the prompt the agent receives, and writing display bytes corrupts the CLI's screen. The report lives in swarm's reserved row, which swarm owns.

One thing goes in before any of this

A message from the phone is not serialised against another message from the phone: two sends interleave into one submitted concatenation and one empty submit. It is live today, and ungating the composer is exactly what makes people send three messages in a row.

It is not part of this drawing and does not wait for it.
