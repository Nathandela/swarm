# Personal and team dispatcher calls

## Outcome and scope

An owner enters a configured ordinary guild voice room to speak naturally to the existing personal Discord dispatcher. The written conversation continues in that owner’s DM. An authorized teammate explicitly invites the dispatcher from an existing linked team discussion. A team hears answers and can address it by saying “Dispatcher”; unaddressed conversation creates no native input. The team thread is the canonical written destination. A bot DM phone call is outside Discord's bot contract. No new manager, shell execution path, public HTTP listener, production credentials, release tag or changes to worker delivery are required. Base b3ac49c includes the merged durable dispatcher delivery change.

## Architecture and responsibilities

1. Default disabled. Explicit connector configuration pins guild, ordinary voice room, existing text discussion, participant policy and per-place speech credential. Refuse mode conflicts, cross-guild links, Stage channels, missing access and group DMs. Personal installation pins its original owner and DM. Team requires a current invitation in its configured admitted thread and current speaker access to that thread. Service startup validates helper availability only when enabled. Stop and removal revert to text operation.
2. The existing Discord Gateway remains the sole owner of the bot connection. Opt-in adds guild and voice-state intents, never privileged message content to personal mode. Build a fresh roster from GUILD_CREATE with continuous updates. A Gateway disconnect, unavailable guild, permission uncertainty, participant change or loss of owner authority synchronously closes the current output gate and invalidates the old generation. Revalidate before resuming. One active room per guild, bounded reconnect, idle timeout, hard call limit. Never replay old voice events from the durable Discord text spool.
3. A supervised Node helper using a pinned DAVE-capable @discordjs/voice receives only the selected guild voice session material via inherited pipes. Validate channel, guild and op 4 before forwarding a helper request through the Go Gateway. Forward matched VOICE_STATE_UPDATE and VOICE_SERVER_UPDATE, accept either order. Require DAVE and modern transport; disable fallback. Do not give the helper the Discord bot token, OpenAI key or manager credentials. DAVE authenticates the media leg; the bridge necessarily processes plaintext. Decode per-speaker Opus 48 kHz into paced 24 kHz mono PCM16LE and reverse for playback. Bound frame size, backlog, silence and drift. Drop stale media on barge-in and teardown. Never record PCM to the ledger or logs.
4. A Go call coordinator binds every frame and event to the current call and generation. Bind each speaker using Discord identity; never use voice recognition for authorization. Personal requires exactly the owner plus bot. Team restricts room and linked discussion audience, explicit enrollment/consent before forwarding audio to the named speech provider, and per-speaker isolation. Revoke on late joins before output; explain that Discord roster events carry latency. Filter overlap; if attribution is uncertain require repetition. Suppress bot/self audio. In team mode, detect an addressed utterance before opening native admission; require an explicit address on each new command. For a first release, isolated utterance transcription of consenting team speakers can recognize the address, then route only addressed turns into the live context. Measure privacy, cost and turn delay of that choice.
5. Reuse Swarm's Live socket and separate BYO speech key. Wait for session.started, retain delegation.id and transcript cursors, assemble each finalized owner utterance once, bound quiet/tail time, and send commentary back with the same delegation ID. Never infer native work or success from generated speech. Handle late text, split Unicode, pending clarification, stale delegation, session expiry, malformed input and canceled playback. Personal barge-in drops old speech, not an in-flight worker. Only an explicit, scoped native cancellation with an observed receipt can announce cancellation.
6. Extend the actual discussion admission ledger with a typed voice origin. Keep text-origin validation unchanged. A pinned tuple of installation, discussion, historically selected supervisor, call, turn, speaker, generation and digest is verified by the connector. The application generates the stable native input ID. Persist before first side effect; replay returns the existing result, conflict refuses, uncertainty reconciles. Recheck speaker, room, current discussion policy and generation immediately before admission; preserve manual pause, parked recovery, native permissions and action receipts. Never fabricate Discord message IDs, publish as a human, feed terminal keystrokes or create a second voice manager.
7. Use canonical manager publication with its original audience, attempt and body digest. Keep the normal written outbox authoritative, and independently suppress duplicate/late spoken playback. Verified progress may be spoken while work runs. Spoken preview can paraphrase; preserve identifiers in text. Stop voice forwarding on audience mismatch. Hangup cancels provider work, drains/kills the helper and releases bounded buffers; existing native work completes into the original text destination.
8. Operator visibility: disabled/ready/active/unavailable with a reason; allow inspection of call/turn IDs, queue drops, DAVE state, time to first media, admission and first playback. Exclude credentials, transcript bodies and raw media from diagnostics. One-click/command opt out of calls; text and existing connector startup remain functional. Bound active connection cost and stop paying after disconnect.

## Review decisions before implementation

Astra and Sol independently read the full plan against b3ac49c. The text spool already discards non-message frames. Preserve this and test a sentinel voice token. RESUMED alone supplies no full roster. Disable media until a fresh GUILD_CREATE; never trade text replay integrity for reconnection speed. Require read/history and applicable private-thread membership for every human listener and speaking/write authority for each admission. A permission event must invalidate earlier decisions even when the room roster is unchanged. The helper gets a minimal environment, with no inherited credentials. Test parent-environment sentinels and a blocked child.

OpenAI output PCM on the speech-input connection lacks a delegation identifier. Discard unsolicited audio from that connection. A local cue can acknowledge verified admission. Use an isolated render fed only the canonical scoped publication for externally audible results. Assert injected synthetic success before native evidence plays no bytes. Validate late, duplicated and interrupted emissions at the final output boundary.

Sol traced native pre-cutover and post-cutover checks to the controller. Model the voice coordinate as a comparable optional value and preserve old text-origin hash bytes. Resolve historic supervisor selection including legacy empty socket bindings. Require live call and speaker authority before queued admission crosses into native input. After that cutover preserve the durable grant and normal written publication subject to current audience policy, even after hangup. Real admission IDs, operation hashes and worker lineage remain authoritative. Key replay by call and turn and compare speaker, body and binding. The written outbox remains independent of optional speech.

Implementation ownership: Sol for native admission, gateway, DAVE/media and speech; Luna for configuration fixtures and operator instructions; integration owner for call policy, lifecycle and cross-lane checks; Astra for independent review of changes. Capture actual usable artifacts per lane. Remaining hardware and account gates require a separately authorized test installation.
