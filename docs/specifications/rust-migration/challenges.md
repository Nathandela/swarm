# Independent challenges to the migration design

Read this during the first design review and again before cutover. The table identifies ways a plausible implementation can pass its own tests and still fail an existing user. Each row names evidence that could change the decision. These are proposed experiments, with historical observations identified explicitly.

## What would invalidate the architecture

* If representative calls need a helper with a separate runtime, retain that signed optional component through its qualification window and record the actual install dependency. A claim of a single self-contained executable then applies only to the core terminal product. Retiring the helper requires an independently observed media replacement.
* If a proposed Rust terminal library fails grid or keyboard fidelity on real supported emulators, change the engine or renderer before proceeding with cosmetic work. The stable boundary is the PTY plus observable terminal behavior. A new widget implementation can still pass.
* If independently executed upgrades cannot reverse post-takeover work, switch the rollout to a drain-first checkpoint with explicit bounds on activation. The release reviewer must see what happens to newly created discussions, shared-provider jobs and pending external effects.
* If an enabled but seldom-used operation is absent from a smoke run, keep its evidence cell open. Measure full-parity coverage as a count of individually enumerated reachable behaviors and required environments. A percentage of Go tests ported hides missing entry points.
* If wall-clock evidence shows no meaningful performance gain, publish the measured result and investigate with an allocation, wakeup or IO trace. Preserve the original user-level budgets and report independent resource changes. A rewrite alone supplies no speedup evidence.

At sign-off the independent reviewer selects the negative controls, inspects first-failure artifacts and runs one complete cross-owner scenario from the packaged candidate. The implementer provides a clean, reproducible environment and a manifest of expected outcomes. Unexplained failures, uncertified stores or ambiguous delivery remain explicit blockers for their affected cohort.
