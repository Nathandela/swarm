## Protocols and failure semantics

1. Connector persists a verified admission before native dispatch. Text identity includes source message and admission revision. Call identity includes installation, discussion, historic supervisor, call, generation, speaker, turn and digest. A duplicate yields the original receipt. The same key with different content conflicts. The durable connector-to-controller handoff has a read-by-ID operation so recovery can resume between writes.
2. Only one manager may act for a discussion. Bind its grant to the historical supervisor endpoint, session and incarnation. Native input, parking, replacement and old-manager retirement use observed custody/process facts. A deadline yields a diagnostic or bounded reconciliation. Manual terminal input suspends automation until exact instance and external-input count reconcile. Unknown startup dialogs preserve drafts and yield a specific action. A manager deleted intentionally may be replaced only under the current deletion and startup proof rules. [Startup and replies](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/verification/dispatcher-startup-and-replies.md) · [Recovery](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/verification/dispatcher-resilience.md)
3. Authenticate a worker note against discussion, parent, job, attempt, session/instance and originating supervisor, then persist before wake. Retry preserves original note, bytes and attachments. One noisy worker cannot starve another discussion. Preserve a verified worker after manager retirement or connector restart. Read a large note through a bounded prompt preview and exact evidence reference. Distinguish a worker turn, a completion note and an observed visible result. [Worker notes](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/verification/dispatcher-worker-notes.md)
4. A publication key commits to original audience, operation, content, ordered file hashes and recipient. Pin immutable bytes. Persist a chunk/nonce before crossing the network. Observe REST/Gateway receipts or exact history from the same audience. A definitive rate limit can retry per the recorded operation. A possibly delivered POST remains uncertain and accepts late receipts across restart and nonce expiry. Withdrawing authorization precludes new send. A canonical written receipt and a voice playback observation advance different states. [Outbox](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/discord/teammate_outbox.go) · [Publication observation](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/discord/publication_observation.go)
5. On personal reconnect, repair the DM from the durable verified cursor, page only within scope, handle edits/deletes and preserve native FIFO before admitting fresh call turns. Known guild threads can recover missing context after a gap. Surface uncertainty about unobserved new mentions. Keep active-worker, reply and once-per-stretch wait evidence. On v0.29.22 routine waits require two quiet minutes and an exact running linked worker. Genuine output goes first. Obsolete attempted waits become passive while late receipts may still settle them. Without an eligible worker, exercise the ten-minute stall notice and cessation of polling. [DM repair](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/discord/personal_reconnect_test.go) · [Wait notice cases](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/discord/teammate_wait_notice_test.go)
6. Keep raw media ephemeral and bounded. Authenticate speaking identity from Discord. A fresh roster and permissions, current generation and per-speaker consent authorize forwarding and playback. Close the gate synchronously on observed membership/grant/permission/key/helper loss, independently of stalled native admission. Inactivity and hard caps terminate paid media. Hangup leaves admitted native work bound to its canonical text audience. Join requests, session credentials and PCM stay outside text replay. [Branch call acceptance](https://github.com/Nathandela/swarm/blob/da7b9f2dfa7e2c6960bd860a72459c0448845c82/docs/specifications/dispatcher-call-resilience-cycle.md)

## Challenge the design with repeatable experiments

- **Two binaries versus one bot.** Differential offline runs use separate state, ports, local identities and recorded traffic. Never point both connectors at the same live token/supervisor. For a real canary use a designated app, two consenting team participants, private guild and separate personal test DM. Record the *serving* version, scope and exact process behind each response. Real external messages and live participants require an authorized test window. Use the designated foreground PID or uniquely named test unit for teardown. The existing generic disconnect can target the user's regular service. [Live trial and rollback](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/verification/dispatcher-resilience-shared.md)
- **Packet ordering versus human observation.** Simulate duplicate/reordered events, 429, ambiguous 5xx, lost REST ACK + late Gateway receipt after 90 days, connector exit before/after commit and full disk. Check exact counts and absence of cross-discussion side effects with a virtual clock. Display Linux/macOS side-by-side screenshots of dispatcher/worker rows and compare JSON status projections with secret-free traces. Keep human review for attribution, phrasing of actionable notices, latency and listener experience.
- **Media helper versus all-Rust.** Start with the existing pinned DAVE-capable media helper across a private pipe so the Rust control migration has a measured reference. Spike a Rust media implementation separately against identical DAVE rekey/participant, Opus pacing/loss, parent exit and x86/ARM packaging fixtures. Require full private/team human trials and locked dependency provenance before replacement. Packaging the proven helper is an explicit native dependency exception while evaluating a full Rust replacement. Substituting transport on architectural taste alone would make faults in orchestration and media indistinguishable.
- **Timing versus progress.** Replay the 480 sub-frame click alignments and positive short intentional stops, attribution overlap and delayed older transcript after fresh playback. Track raw counts plus p50/p90 from last human syllable to first useful acknowledgement, first substantive result and last audible old sample on the same clock. Physical targets from the call branch are 2.5 seconds median to useful acknowledgement and 500 ms median to audible stop. Missing observations count as failures. Hosted first-output PCM and native completion time answer different questions. Keep the reported team full-utterance delay (~2.6 s synthetic) visible until listener evidence exists. [Call resilience evidence](https://github.com/Nathandela/swarm/blob/da7b9f2dfa7e2c6960bd860a72459c0448845c82/docs/verification/dispatcher-call-resilience-cycle.md)
- **Rollback versus an irreversible send.** Exercise switches with pending files, requests, committed native inputs, compaction and late receipts. Require one durable writer per identity and independent old/new version detection. Revoke the old service's activation before arming the new one. Rollback must preserve uncertain sends and current worker custody. A single database transaction cannot atomically commit a Discord POST.
- **Qualification boundaries.** Linux native frozen trials with real Codex workers and synthetic Discord coordinates proved original-worker survival and reverse-order return across both supervisor and connector restart. That branch's full Linux race suite failed (two packages); focused macOS replays passed. Its archived helper ran on Mac/Linux. Actual Discord audio, volunteer listener timings and a published-build voice rehearsal remained open. The historical text live trials and new mainline file fixtures are separate evidence. Repeat local native gates and live qualification on candidate and installed artifact before accepting each release claim.
