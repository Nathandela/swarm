# Five operator acceptance trials

Perform these at M11 from the installed artifacts. Repeat when an affected contract changes. Each run produces an observation per checkpoint, its exact build/host, and the first divergence. Replay deterministic inputs in isolated Go and Rust arms first. Then have a second operator follow only the task and visible product guidance. An agent can drive the actual terminal and collect sanitized screenshots. Two consenting people in a real private guild supply the hearing, timing and attribution observations in trial 4.

Use ephemeral OS users or isolated test machines, distinct data roots, owned Git worktrees, disposable provider profiles, short socket paths, and a distinct test bot and threads per live arm. Seed identical logical fixtures with unique per-run nonces. Record native identities separately within each arm, and verify every cross-step relation before comparing projections. Stop if a path, supervisor, native conversation, Discord app, room or user belongs to an ordinary installation. Never send from both arms using one bot or live discussion ledger. Preserve sanitized first-failure artifacts and tear down only proved trial resources.

## 1. Recover my worker from a narrow terminal

Seed two distinguishable running workers in the same Working section and two ended rows. The foreground fixture echoes a unique token including a wide character. Open bare `swarm` in a 40×8 real terminal. On a running row press Left to fold Working, then Right to expand it. Check that its header and then the first member are on-screen. Use Down or Up to select the named fixture, Enter to attach, type the token and Enter. Press Ctrl+Q to return. Reattach and press Ctrl+N then Ctrl+P, checking the two native screens and returning to the original worker. Resize to a desktop width and back while the worker prints. Capture initial, folded, attached, detached and resized frames with cursor, dimensions and styles. The agent checks cells and exact delivered bytes. The human checks that the active target remains identifiable and the return hint remains usable.

Close the client terminal while the fixture stays active. Reopen the board, confirm the same session and native instance, and find the token. Remove a different row during keyboard navigation in a second run. Fail on a command entering the wrong worker, a forwarded detach byte, an orphan, hidden focus, a truncated wide character that changes adjacent cells, or an unexpected terminal mode after exit. ## 2. Ask another agent and recover a fast reply

Give an agent an isolated authenticated test session with a predetermined response. A second agent runs `swarm --pilot`, takes the returned context path and runs the operations below with the printed path and the worker’s stable ID.

```sh
swarm pilot --context "$context" roster
swarm pilot --context "$context" open "$worker"
swarm pilot --context "$context" send "$worker" --text "Return the fixture marker $marker"
swarm pilot --context "$context" watch "$worker" --once --after "$cursor" --timeout 1m
swarm pilot --context "$context" view "$worker"
swarm pilot --context "$context" exit
```

Use the send result’s `worker_data.watch_after_cursor`. Arrange for the answer to arrive before watch starts. If the first event concerns earlier work, rearm with the consumed event cursor until a fresh view contains the marker. Compare JSON keys, receipt class, source/target identity and exact outbound text. Read a worker reply containing an instruction-shaped string and confirm it remains under worker data. A timeout or submitted receipt alone cannot satisfy the trial. In a second run, disconnect the watch and resume from its last fully processed cursor. The agent reports the actual reply and closes its own context. An expired or foreign context must never submit work. [Pilot operator contract](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/operations/pilot.md)

## 3. Hand off to another CLI without losing the parent’s checkout

Create a disposable Git repo with a committed fixture and a unique uncommitted parent edit. Inside the managed source session, write a short context document in trial scratch and run the following with a qualified second CLI and its native fixture profile.

```sh
swarm handoff --cli "$other_cli" --name parity-child --supervision manual --context-file "$context_file"
swarm peek "$child" --lines 12
swarm watch "$child" --until needs_input --timeout 1m
swarm send "$child" --text "$answer"
swarm checkout inventory --json
```

Capture the child ID from handoff stdout. Have the fixture explicitly request input, then report its working directory and the committed marker. Inspect the actual parent and child working directories and Git registrations: the child starts from the committed tree while the uncommitted edit remains in the parent. Capture the board lineage, native receipt where available, and child terminal output. The operator should be able to trace which worker asked for input and which answered. Run handoff from outside a managed session in an isolated second trial and require refusal with zero new workers. Fail on a second child, parent mutation, an unowned deletion or a reported completion established only by process exit. ## 4. Continue a team thread in a live voice room

Compare the text/file portions against released main and the call portions against the pinned call build plus its corresponding helper. The candidate must satisfy the whole journey in one installation. Use a private guild, ordinary voice room, dedicated connector, linked test thread, two eligible volunteers and a third informed volunteer who agrees to the trial and deliberately withholds the Discord voice-consent command to exercise the revocation fence. Supply a unique text marker and a tiny plain-text attachment with a known digest in the team thread. Confirm the dispatcher can identify the marker and read the file under its scope. Both volunteers enter the room. Each types a real bot mention followed by `voice consent` in the linked thread. One types `@Bot voice join` using the actual mention. Wait for readiness before speaking.

1. Speak ordinary conversation and check zero native commands. Then A says “Dispatcher, read back the marker and ask a worker for the file digest.” B asks a different addressed question with a second nonce. Check independent speaker identities, native admissions and exactly one canonical answer per request in that thread. Verify observed digest and worker linkage.
2. Interrupt playback, let the observer join and capture the first observed membership change. Require old-generation audio to cease at the gate and forbid new admissions under stale consent. Keep observers’ timing marks, sanitized status and publication IDs. Exclude microphone recordings and tokens from evidence.
3. With valid room authority re-established, submit one delayed worker task. Type `@Bot voice leave` while it is pending. The accepted result must still arrive in the original thread. Check that another channel and the owner DM received none of the trial content. Repeat the administrative suspension via `swarm discord stop-call --state-dir "$connector"` and verify text operation and suspension in `swarm discord status --state-dir "$connector"`.

The harness checks duplicate/out-of-order consent, overlapping speakers, late worker results and delivery counts. The humans judge audibility, familiarity of turn taking, useful acknowledgement and interruption lag on a common clock. Report separately the cold first turn and ten warm turns. Stop on unexpected authority or room membership. Release is blocked by a wrong audience, unintended native work, unreconciled duplicate, helper mismatch or missing listener evidence. [Call controls and configuration](https://github.com/Nathandela/swarm/blob/da7b9f2dfa7e2c6960bd860a72459c0448845c82/docs/ops/discord.md) · [Text/file qualification](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/verification/discord-discussion-files.md)

## 5. Upgrade, create work, then recover it

Use two disposable installed cohorts, one Homebrew-owned and one self-managed. Start with signed Go artifacts and the historical sibling layout. Save package ownership, hashes, timer state, session IDs and native identities. Prepare one live attached fixture, one parked dispatcher with a pending test delivery, and a job due after cutover. Run the Go `swarm doctor --json` and `swarm ls --json` in the isolated environment. Check the bridge preflight required by the transition plan. With live writers present, an unsupported mixed pairing must defer without touching a process or accepting new work twice. Follow the documented first-hop installer for that cohort once safe.

Through the installed Rust board attach to a recovered fixture, submit a fresh marker and start one new worker. Let the pending delivery settle against the fixture transport and the job reach its recorded attempt. Stop candidate writers and exercise the documented dirty rollback path. Check the staged and actual executables, reader/writer compatibility, same stable conversation identity, recent marker, new child, timer ownership and exactly one external effect. Where dirty rollback requires roll-forward recovery, require an explicit refusal before mutation and prove that the preserved candidate store still serves the newer records. The operator must be able to tell which installation is authoritative using local diagnostics.

Repeat from a checkpoint with a corrupt signed asset and with a simulated interruption between activation steps. Fail on lost post-cutover work, wrong-package mutation, concurrent writers, an automatic retry of an uncertain send, a reinstated phone service or a preflight that says ready with unknown live custody. Record actual user-visible messages and hashes. These drills run before a production canary. [Installation and rollback contract](transition.md) · [Known updater incompatibility](challenges.md)
