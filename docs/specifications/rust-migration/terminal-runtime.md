# Terminal, session runtime and continuity

This chapter defines acceptance against shipping Go v0.29.24 at `a716dd50a5faf746ce6f0831fc31d0d73b06ffeb`. Historical source links point to the v0.29.22 contract at `f26648d6`. A user can start a discussion, leave it running, restart the supervisor, find the same discussion, and reconnect to the same live terminal. That journey is the first integration slice. The built program determines the contract when early specifications differ from shipped behavior. [Reference pins](README.md#pin-the-two-references)

## Ownership and failure boundaries

| Owner | Owns | Contract at its boundary |
|---|---|---|
| Terminal front end | Selected endpoint/session, drafts, viewport, focus, geometry, display preferences, connection generation and terminal modes | A pure update function turns events into state and requested effects. A single terminal owner paints or hands the device to attach. Every effect returns with its originating generation and target ID. Quit, cancellation and early errors restore the terminal and release readers. |
| Local supervisor | Singleton lock and owner socket, roster, durable lifecycle operations, reconciliation, controller grants, command serialization and status projection | One serialized mutation stream per session. Bound I/O separately so a blocked peer or provider cannot freeze unrelated sessions. An accepted write, provider acceptance, uncertain delivery and completion are distinct outcomes. |
| Per-session process | PTY master, VT grid, live output order, terminal query replies and native worker ownership where the adapter contract grants it | Maintain child lifetime across supervisor or client exit. Serialize feed, resize, snapshot and subscription at a common boundary. Never put a slow consumer or disk writer on the PTY drain path. Containment is limited to the processes the adapter actually owns. |
| Session storage | Per-attempt metadata, native discussion identity, compact replay/custody records, cleanup receipts and workspace ownership | Session directories are the durable registry. Preserve platform identity tokens, write-once native IDs, attempt lineage and explicit deletion semantics. A provider retains its native history. |
| Discord and local clients | Authorized commands and incoming events | Use the same lifecycle, message and identity operations. The UI routes linked dispatchers through their owning endpoint. The dispatcher section, parked manager rows and worker identity must survive removal of standalone voice plumbing. |

Begin with modules at these seams. Only split a library target when a second process or test tool needs that contract. Use an explicit tagged command/reply model inside Rust and a narrow translation at the wire boundary. A single global state mutex enclosing filesystem, provider and socket operations would couple every session's latency to the slowest device. Conversely, an actor per screen row or per terminal cell adds coordination without ownership. Treat “shutdown” as scoped to the owner: quitting the board releases its socket, stopping the daemon closes its tasks, killing a worker is an explicit separate operation. [System invariants](../../invariants/system-invariants.md) · [Linked dispatcher board](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/tui/dispatcher.go) · [Shim design](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/adr/ADR-001-per-session-shim-processes.md)

## Contract freeze before choosing libraries

1. **Wire.** Both local sockets use a four-byte big-endian length including the one-byte type, followed by payload. Types 1–4 mean control, output, input and snapshot. Max frame length is 1 MiB. A control body is JSON. Record version, optional fields, absence/zero/null behavior, request/reply correlation, timeouts, caps, and error behavior from real peers. The checked-in shim hello currently uses version 2. Namespace IDs by endpoint and validate the local component before filesystem access. Produce a golden transcript for each retained local operation and an omission list for removed operations. [Frame codec](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/wire/wire.go) · [Control codec](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/protocol/codec.go) · [Shim version](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/shimwire/version.go)
2. **Snapshot.** Preserve v1 geometry, run widths, colors, styles, alternate-screen flag, visible cursor and sanitized title. Model absent mouse/input modes as unknown. The initial snapshot can span frames. Advertise the exact length and negotiate chunking on the inner hop. Accept zero, single and multi-chunk snapshots under a total deadline. Reject overshoot, premature live bytes and incomplete transfer. A snapshot-only grid read must leave an existing controller attached. A superseding attach requires a fresh snapshot boundary. Apply the Go chunk completion/trailing-frame rule from the amendment. [Snapshot schema](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/vt/emulator.go) · [Both-hop negotiation](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/adr/ADR-002-protocol-control-data-split.md)
3. **Attach.** Keep binary output, terminal replies and user input distinct. Snapshot projections sanitize control content. Raw live passthrough has a different contract. Chrome/reset bytes may only reach the outer terminal. Check which endpoint owns query replies at each phase. Preserve normal and alternate screens, hint row, scroll margins, cursor, bracketed paste and negotiated input modes. Mouse capture for the optional attached return button can affect native selection. Default it off, decline unknown mode ownership and cancel armed gestures on changes. [Raw byte witnesses](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/attach/g4_ptybytesacred_test.go) · [Query replies](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/shim/replies_test.go) · [Attached button amendment](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/adr/ADR-035-mobile-terminal-navigation.md)
4. **State.** Inventory actual files from clean launch, native resume, dispatcher, schedule, failed cleanup, parked and crashed sessions. Describe each field's reader, writer, lifetime, permissions and restart behavior. Copy or synthesize sanitized fixtures for generic v1, OpenCode v3, provider-runtime v4 and Hermes-native v5. Preserve v2 offline refusal and unknown-newer-schema refusal until a separately tested conversion exists. Existing metadata can describe an old provider runtime after rotator commands disappear. Unresolved provenance must stay quarantined with an actionable reason. A fresh login must never silently rebind an old identity. Preserve untouched records on failed inspection. [Store](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/persist/persist.go) · [OpenCode binding](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/persist/opencode_binding.go) · [Atomic state contract](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/adr/ADR-003-persistence-schema.md)
5. **Retention.** Maintain the fixed 64 KiB identity discovery ring plus header, 0600 files and 0700 state directories. Keep generic interaction content bounded and live. Preserve durable obligations and recent operation outcomes through crash. Keep provider history and user repositories outside Swarm cleanup. Use compact retryable ownership records on failed worktree cleanup. Test full disk, partial writes, rename failure and crash after commit before acknowledgement. Add a directory-sync durability decision with fault evidence before claiming power-loss durability, since the current metadata writer syncs the temporary file and renames it. [Retention amendment](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/adr/ADR-033-live-only-supervisor-storage.md) · [Deletion evidence](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/verification/discussion-deletion.md)
6. **Platform identity.** For Linux match PID plus kernel start ticks. For macOS match PID plus kernel start time in microseconds. Preserve units in snapshots and durable records. Only the holder of the flock may repair a stale socket. Check birth identity before adoption and signaling and require the adapter's ownership evidence before acting on a native worker. Exercise exit/reuse windows, supervisor death during launch, sidefile-only children, legitimate descendants and shared Hermes ownership. ## Scoped implementation sequence

These are suggested Beads scopes. Each should end in a runnable local witness with its inputs and both observed results. Fail a dependency gate before expanding a slice.

| Slice | Depends on | Deliverable and pass condition |
|---|---|---|
| T0 Reference corpus | Pinned Go build | Generate golden frame conversations over sockets, metadata fixtures and terminal captures from the same binary. Attach a digest, host/terminal settings and behavior label to each. Reproduce one deliberate one-cell visual change and one wrong input byte as failing comparisons. |
| T1 Read-only board | T0 | Rust command connects to an isolated Go daemon, subscribes and hydrates a roster. Paint wide and compact screens with the initial selected identity, status and elapsed time. Kill daemon mid-list, restore it, change selection mid-reconnect and confirm no stale reply overwrites the new generation. |
| T2 First live session | T1 | Use the Go supervisor's existing launch/attach path for an ordinary synthetic agent. Deliver keys through a real PTY, render initial snapshot, resize, detach, redisplay the selected row and quit to a clean shell. Capture separate device output and child input to catch chrome leakage. |
| T3 VT and shim | T0, T2 for interop | Feed split real terminal captures, export snapshots and query replies; spawn an owned child and drain it with zero clients. Under the Go daemon attach a Rust shim, then supersede, stall the old client, kill the daemon and reconnect. A VT dependency requires passing the corpus on both host OSes before selection. |
| T4 Lifecycle store and supervisor | T0, T3 | Rust supervisor opens a *copy* of old state, accepts retained owner operations, reconciles live Go and Rust shims and writes records the rollback version can read. Race two daemon starts, exit/launch events, writes and confirmations. Stop between each durable step and recover on the next invocation. |
| T5 Board flows | T1–T2; command owners may land independently | Port general and More menus, responsive/adaptive fields, forms and text editing, discussions/lineage, selection, tags, rename, launch, resume/relocate, worktrees, handoff, schedule/manager, dispatcher and options. Record every retained key and pointer action by mode and target. Every menu entry needs an eligible and ineligible scenario. |
| T6 Native attach and recovery | T3–T5 plus each provider | Confirm active provider screens, terminal queries, trust dialogs, signals, baseline-only native resume and child ownership. Inject disconnects during attach setup, partial snapshot, pending write and provider shutdown. Run scripted peers offline first and the deployed native binary per adapter/platform when available. |
| T7 Transition rehearsal | T4–T6 and retained feature gates | Run the interop and disk rehearsal below. Exercise automatic upgrade deferral, install-path replacement, exact existing worker identity and rollback. Authorize release from local signed evidence only after supported transition cells pass. |

A practical Rust dependency evaluation uses the same capture set for every candidate terminal emulator/parser. Score correct VT replies, grapheme cell widths and style, input modes, bounded memory, reset recovery, ability to serialize state and measured throughput. An unsuccessful candidate is cheap to discard before app-level binding. Test layout libraries through the actual outer PTY. A library's off-screen text buffer cannot demonstrate termios restoration, accidental event reports, focus loss or native application interaction. Isolate the platform syscalls in the PTY/process module and audit each unsafe boundary for descriptor lifetime and signal ordering.

## Interoperability, cutover and rollback

For one pinned supported Go version, run the full Go/Rust client × supervisor × shim cube on native Linux and macOS. The all-Go cell calibrates the oracle. The all-Rust cell proves independence. In each mixed cell record negotiation, capability subset, attach and terminal state, necessary owner operations, native identity, recovery, signals and cleanup. Pin a shim process across the supervisor replacement itself and compare PID, birth token, provider thread, old pending operation and fresh grid. Test version-skew refusal separately. Shims from an unrelated wire generation retain their existing documented offline migration boundary. Reverse interoperability for retained operations is an explicit release criterion if hot rollback is offered. Remove migration-only harness adapters from shipping targets.

Use isolated roots and never run two supervisors against the same live installation. A rehearsal starts from a scrubbed, offline snapshot. Compare before/after manifests and per-role outcomes, including unknown keys and protected files. Keep the write schema and per-role identifiers readable by the previous executable throughout the rollback window. A backup can restore pre-cutover data but cannot safely reverse work users did after cutover. Rehearse Go→Rust→Go with intervening launch, rename, resume and receipt operations. Disable rollout on irreversible write, unresolved identity, failed restore, or unsupported active worker. If bidirectional compatibility proves infeasible, ship only after an explicit maintenance-window proposal with drain, inventory, export/verify, user-visible downtime and resumability evidence. Never automatically terminate sessions to make the migration easier.

The final rehearsal should leave an active session and an idle session behind, an upgrade deferred where policy requires, an old shim with matched identity, a replaced executable, a restored shell and a working board showing the correct names and statuses. Compare input bytes and real process identities as well as screenshots. A visually identical board can conceal duplicated submissions, a new provider thread or an orphaned PTY.
