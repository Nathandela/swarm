# Retirement, distribution and the first upgrade

The release unit is the verified set of bytes the user actually runs. A Rust binary passing a local test does not establish that an old installation can reach it, that a new daemon can still launch a compatible shim, or that a Discord call finds matching media code.

## Scope by installed effect

| Surface in Go | Migration and retirement proof |
|---|---|
| Phone clients and remote transport | Remove Android, iOS, gomobile facade, phonecore/phonesim, pairing, push registration, relay, gateway, device keys and phone-only grants. Remove mobile publishing, GCP deployment, relay Worker and push-container delivery from the Rust branch's live build/docs. Inspect help, daemon capability negotiation, socket listeners, environment reads, signed archive and cask inventory. A clean install creates none of those resources. Existing remote credentials and external deployments require a separate operator-owned decommission inventory; code removal cannot revoke a deployed credential or uninstall a running unit. |
| Native voice app | Retire desktop panel, phone enrollment, voice SSH transport, standalone device playback/capture, service and public `swarm voice` workflow. Migrate the discussion controller, manager identity, receipts, speech/call policy and qualified media helper to their retained owners. A native voice installation fixture must classify which records carry Discord obligations, with a refusal on ambiguous ownership. The narrow-terminal board, attached return affordance and ordinary SSH terminal sessions remain supported. |
| Account rotation | Eliminate stored account selection, credential switching, login-worker subprocess, usage panel/switching controls, rotation jobs and automatic cross-account lifecycle. Retain the installed CLI's ambient login, identity checks, deliberate native sign-in recovery and the evidence necessary to protect an old record from incorrect reuse. Preserve [`swarm relogin`](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/cmd/swarm/relogin.go) including automatic repair when the external provider identity stamp changes, plus explicit `--force` for same-account sign-in that the watcher cannot detect; qualify ordinary authentication expiry, native sign-in and session recovery independently of removed Swarm-managed switches. Rehearse a pending switch, blocked writer, old profile and healthy native login separately. Uncertain account operations block migration of the affected record until resolved offline. No provider credentials migrate into Rust custody. |
| Shared code and tests | Classify by reachable behavior. `internal/skeleton`, `cmd/swarm`, `internal/protocol/schema`, `internal/tui`, `internal/voice`, `internal/converge` and `internal/upgrade` contain shared contracts. Keep local authority, journals, diagnostics, timers, native Hermes gateway, worker receipts and Discord service operations as appropriate. Keep fixture traces for retained behaviors in mixed packages. Remove deprecated provider selectors, remote dashboards, relay fixtures, stale links, doctor rows, package artifacts and startup probes from active targets. |
| State already on a user's machine | Inventory all configured places, canonical roots, live processes and user services, including the Discord supervisor location from its stored config. Resolve ownership before acting. Native provider history, provider credentials, external repositories and user edits are user-owned. Leave retired secrets and unrelated files untouched by default. A separately invoked retirement action can disable precisely identified Swarm units and archive/remove enumerated Swarm-owned files after presenting scope. Reinstall/rollback tests must cover those optional actions. |

Use the [CLI dispatcher](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/cmd/swarm/main.go), [mobile facade](https://github.com/Nathandela/swarm/tree/f26648d69086e329132ac7849954d2f29a895387/mobile), [assembled runtime](../../../internal/skeleton), [Discord supervisor selection](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/discord/config.go), [offline migration guards](https://github.com/Nathandela/swarm/tree/f26648d69086e329132ac7849954d2f29a895387/internal/loginmigration), [checkout inventory](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/ops/checkout-inventory.md) and [storage cleanup](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/ops/storage-clean.md) to derive the records. At M0, produce one disposition per command/alias, setting, socket, unit, package, artifact and persisted record family. At M10 compare the union of Cargo targets, feature combinations, archive manifests, cask links, startup effects, completions/help, docs index and syscall/network observations against that ledger. Treat unexpected reachability as a release failure. Formula or archive references to retired siblings count as broken installations.

## First-hop obstacle

The v0.29.22 updater verifies Ed25519 over the checksum document, verifies the archive digest, then extracts only bare regular files named `swarm`, `swarm-remote` and `compat.json`. When an installed `swarm-remote` sibling exists and the new archive omits it, activation refuses the mixed pair. The old extractor also skips new Discord helper members. Removing mobile and uploading a familiar-looking tarball would leave installed users stranded or without call support. The release card's account fields describe old schema readers, not a reason to recreate account selection. [Extraction](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/upgrade/transaction.go) · [Activation and interrupted convergence](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/upgrade/activate.go) · [Card](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/upgrade/manifest.go) · [Call-branch archive contents](https://github.com/Nathandela/swarm/blob/da7b9f2dfa7e2c6960bd860a72459c0448845c82/.goreleaser.yaml)

Use an explicit, locally invoked first hop. Test self-managed installation from independently signature-verified archive bytes and a new cask upgrade from an actual v0.29.22 cask. Supply human-readable instructions in the Go release channel before making Rust the default. Detect a Go-owned installation and guide migration to the chosen supported distribution, preserving provider and Swarm state. Retain package-manager ownership for Brew, dpkg and rpm. A Go source install at the old tag remains a historical recovery path. Document Rust source installation and how ownership is recorded so the self-updater cannot overwrite a package/toolchain-owned binary. Verify deferred unattended timers remain safe against the actual public release metadata, including single-binary old installations where the sibling refusal does not apply. If the old timer could activate the candidate prematurely, use a separate opt-in release channel until a proved migration-aware Go updater or a deliberately staged owner transition is available. The later Rust-to-Rust updater owns future compatible transactions. [Ownership detection](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/upgrade/ownership.go) · [Timer and recovery operations](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/ops/auto-upgrade.md)

## Operator rehearsal on disposable copies

1. **Discover.** Report installed bytes, resolved paths and owners, per-place state/config/locks/sockets, daemon identity, shim birth identities, timers, Discord connector/helper versions, storage footprint, free bytes, active sessions/workers, pending work, account/remote remnants, format versions and unknown files. Mask secrets. Report read errors and stale/ambiguous ownership explicitly. A dry run launches no service and writes no state.
2. **Prepare.** Use isolated homes, test guild/fixtures, local services and provider data copies with restrictive modes. Keep an immutable copy of binaries, units and retained state with a file manifest, mode, digest and source path. Use filesystem snapshots when suitable, otherwise quiesce writers before copying. Never copy a live directory piecemeal and declare it a backup. Demonstrate restore into a second isolated root before touching the source copy. Check disk-full and insufficient-permission paths. Avoid making plaintext copies of credentials outside their existing private custody.
3. **Fence writers.** Establish one owner of each effect, including inbound Discord events, scheduled wakes and provider sends. Stop admitting new work across the change window, drain or durably preserve in-flight effects and prove timer/connector/daemon custody. A stale lock, unreadable record, unclassified unit, unresolved callback, incompatible running shim or unknown effect yields a visible deferral. A Go daemon holding the lock with zero sessions can still launch a new shim from the replaced path.
4. **Stage and activate.** Validate checksums, archive contents, compatibility and installed owner before mutation. Verify the staged executable on the target architecture, prepare all managed files on their destination filesystems, keep rollback slots and persist the phase before the first rename. Recover deterministically if killed before or between renames. Preserve the pending-convergence marker until the installed executable confirms its own daemon and connector situation. Stamp the observed running version and process birth identity, alongside the on-disk version. Cold import runs with both supervisors fenced; live takeover requires passing every proposed mixed cell. [Rollback logic](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/internal/upgrade/rollback.go) · [Unattended restart](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/docs/adr/ADR-020-unattended-daemon-restart.md)
5. **Exercise new writes.** Rename and launch sessions, modify a schedule, accept and finish a worker, create a Discord attachment and receipt, reconnect the connector, start/end an authorized call, then restart everything. Check identities, terminal state, link scopes, pending reply obligations, worktree content, schedule execution count and native thread history. Check an old discussion with outstanding work and an ended session that references retired account fields.
6. **Reverse.** Quiesce new writes, identify post-cutover user work and external effects, and test whether Go opens the resulting records safely. Restore the previous executable via the actual owning installer and reattach only to matched live shims. Preserve post-cutover sessions, edits, schedules, reconciled receipts and provider history. A pre-cutover backup alone discards newer work and cannot undo a published message or a fired timer. Require durable evidence for every externally visible effect. If the rollback version cannot represent a record, hold in a documented recoverable state, inventory the delta and keep Rust available for read/export/reconciliation. Only claim hot rollback for configurations proved in both directions.
7. **Repeat under failure.** Inject abrupt termination after every phase boundary, a full filesystem, unreadable JSON, changed binary symlink, stale socket, package manager replacing a symlink and saved-environment loss. Include an empty install, a busy installation, a machine with several Discord places, a missing helper, and dormant legacy units on macOS and Linux. Run the same rehearsal with a live shim and the daemon down. Run cold/offline downgrade separately where live adoption is unsupported. Record exact pre/post hashes and recovery outcome. Avoid collateral cleanup via process-name matching.

## Locally operated release

Replace the old release graph on the migration branch before any release tag. Remove all event-driven and reusable workflows for the Rust release line, including the old tag-triggered Go publication and push gateway build. A GitHub release is a distribution destination. Build, qualification, signing and publication are separate, explicit operator steps. The release operator must check the default branch/tag workflow behavior before creating a public tag. [Manual Rust preview release](../../operations/rust-preview-release.md) · [Pinned Go release workflow](https://github.com/Nathandela/swarm/blob/v0.29.22/.github/workflows/release.yml) · [Pinned Go release manifest and archives](https://github.com/Nathandela/swarm/blob/v0.29.22/.goreleaser.yaml)

| Stage | Required local proof |
|---|---|
| Freeze | Clean checkout, exact Git SHA/tag, updated baseline drift ledger, pinned Rust/toolchain and dependency locks, dependency/license audit and artifact manifest. Refuse dirty sources and version mismatches. Keep evidence of source tree and environment without credentials. |
| Build | Produce Darwin universal arm64/x86_64 and Linux amd64/arm64 artifacts as supported by Go. Check minimum OS/ABI and actual dynamic dependencies on each. Install the exact bytes on each architecture and exercise PTY/process identity. Cross-compilation alone covers buildability. Smoke tests on the architecture cover execution. Keep the desktop/terminal install usable without a media dependency. |
| Media | Produce the precise helper assets and dependencies from the selected call implementation, pin its protocol/build identity in the release card and verify its discovery by the packaged connector. The call-branch package contains a script, media module and dependency lock. Prove dependency availability on a clean machine and make a real encrypted call before claiming packaged voice parity. A Rust replacement has to earn this same gate. |
| Sign and verify | Generate a compatibility card from constants used by the actual build. Cover the card, binary, call assets and installer with the signed artifact set. Preserve existing Ed25519 checksum verification and test tampered archive, swapped card, missing/wrong helper and wrong key. Keep signing secrets offline from the build logs. The current Homebrew cask strips quarantine for an unsigned macOS binary; distinguish archive signatures from OS signing/notarization and test downloaded first execution under Gatekeeper. [Signing logic](https://github.com/Nathandela/swarm/tree/f26648d69086e329132ac7849954d2f29a895387/scripts/signchecksums) · [Pinned Homebrew reference](https://github.com/Nathandela/swarm/blob/v0.29.22/packaging/homebrew/swarm.rb) |
| Stage and smoke | On a disposable host per install route, install the actual archive/cask, run version/doctor and the board, launch/attach/restart/reattach and close one real session. Exercise the Discord connector and call from shipped bytes, compare signed manifest digests with disk, and rehearse update/rollback. Test a missing daemon remains stopped for diagnostic verbs. |
| Publish manually | Assemble a draft release only after green scoped evidence. Verify downloaded staging assets with the public release key, compare hashes, exercise a limited opt-in canary and inspect owner-visible diagnostics. Promote the tested bytes unchanged, update the tap and installation docs deliberately, then redownload from the public location and run checksum plus install smoke. A partially uploaded draft is recoverable; a partially populated public release cannot be the upgrade target. |
| Close | Record verified architectures, OS, build and provider versions, binary digests, exact commands and unrun gates. Reference immutable evidence from one active Rust operations index. Remove Go build tools, old mobile signing pipelines, release-only tests and language-specific docs from the final active tree after the reference corpus is reproducible from pinned Git artifacts. Keep historical releases accessible. |

**Stop promotion** on data loss, duplicate externally visible effects, unsafe credential handling, wrong process adoption, inability to restore terminal modes, a broken first hop, missing media dependencies, or a rollback that obscures work. Publish a recovery path for every supported install owner before promoting it. During the canary, only one implementation may write to any production place; the comparison arm uses a clone with external effects disabled.

### Build tickets for M10

R1 inventories installation/state and proves read-only preflight. R2 freezes cold and dirty-state fixtures and verifies restore. R3 implements archive staging, owner checks, transition fencing and crash recovery. R4 qualifies self-managed/cask first hop, staged timers and reverse operations across kernels. R5 retires build graph, units, active documentation and package artifacts against the reachability ledger. R6 rehearses the local build, checksum/signature verification, packaged Discord helper, draft download and rollback on each supported install route. R2 and R5 discovery can proceed together. R3 consumes R1/R2, R4 consumes R3, and R6 consumes R4/R5 and the product qualification gates. Every ticket has a read-only preview or repeatable test fixture as its first observation.
