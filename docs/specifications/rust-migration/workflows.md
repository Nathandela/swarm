# Providers, orchestration and daily work

The reference is the behavior reachable at Git revision `f26648d6`. An adapter reporting an installed version, a provider accepting an operation, and a real native conversation completing that operation are three separate observations. Qualify each operation independently. Existing evidence below is a starting corpus for the Rust work. All acceptance runs described here are future gates.

## A worker's identity and its capabilities

Use separate identifiers for the Swarm session, shim incarnation (PID plus birth time), provider instance/generation, native conversation or root, native turn/input/request, and caller operation. A resumed conversation can acquire a new Swarm ID. Multiple conversations can share a checkout. A provider child can share a native root without being a spawned Swarm worker. A viewer can disappear while its native jobs survive. Persist these relationships where they originate. Present ambiguous ownership as unknown throughout the roster, pilot, scheduler and Discord.

Build provider modules around four concrete operations. Compose launch/resume argv and environment without side effects. Bind a live native or PTY owner and report the operations supported by that particular binding. Convert observations into evidence carrying source, scope, sequence and freshness. Execute a permitted effect against exactly that binding. Keep per-provider argv, version checks and protocol decoders together. Use a common session command path for attribution, durable intent, serialization, recovery and authorized receipts. Keep all credential material inside the provider's own login flow. The dispatcher and scheduler can request capabilities through this same path. Their requests must satisfy the same checks as input from a terminal client.

A single Rust module per provider is a workable initial split. A common launch form schema and typed outcomes buy more here than an object-safe trait with a method for every optional action. Select execution mode at bind time. Recheck identity and capabilities at the write boundary. A static five-row registry can populate the picker, while a particular shim lacking registration or running a different backend can still refuse. Keep the fixture-only reference provider outside production admission. ### Removing account management without losing daily work

Retire switching providers' saved accounts, credential pools/capture, identity migration, replenishment or exhaustion-driven relogin and the associated managed homes, UI, commands and timers. Preserve provider-native sign-in, configured native profiles and the ability to surface missing credentials, quota or a permission prompt. Scheduled fallback chooses another configured **agent** with the job's authority. It must never select another login for one provider. An operator's original files and home remain theirs. A dry migration reports references to an old Swarm-managed account home; block affected resumption until the operator establishes a compatible native identity. Do not translate home selectors silently or read/export their secrets. [Old managed environment proof](../../../internal/daemon/manager_login.go) · [Scheduled authority policy](../../../internal/scheduledexec/policy.go)

Preserve native-session repair after an external sign-in. For example, after a user signs back into the same provider account, an old process may still hold a revoked token. Exercise the existing relogin dry-run, opt-out and explicit force paths, deduplication against the watcher and retained native conversation after replacement. Swarm must never pick or switch an account during repair. [Native repair command](../../../cmd/swarm/relogin.go)

The Go manager accepts a validated managed-login environment as well as a native one. Port its native-origin refusal checks and exact role binding. Qualify both Claude and Codex managers using ordinary provider authentication on each release host. A shell authenticated under the user's account can differ from a timer-launched or supervised native process. Record the provider's observable authenticated/refused result and local selectors with secrets redacted. Do not synthesize replacement credentials or clone profiles. For a mixed outstanding refresh/switch record, keep the original backup intact, import the proved CLI-refresh obligation separately, and surface ambiguous obligations for manual recovery before any automatic stop.
