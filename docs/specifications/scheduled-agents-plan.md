# Scheduled agents in Swarm
## Product contract
One per-user job catalog on each host. Board → More → Automations → New starts blank. Schedule in this directory prefills the selected session directory. Both use the same editor. Personal templates snapshot prompt text. An empty library starts blank. Editing a template leaves existing jobs intact. The form keeps the draft on validation errors and previews the time zone, next triggers, authority, ordered CLIs, directory and dispatched prompt before saving.
## Milestones and acceptance gates
1. **Host probes.** Verify the supported Go toolchain and isolated CLI build on macOS and Linux. Exercise a benign toy repository, overlapping Git worktrees, timer delivery and a replayed occurrence without touching other sessions. Check daemon cold start, timer environment, shell-independent directory resolution and SSH alias inheritance. Capture OS/tool versions and explicit skips.
2. **Private domain and storage.** Job definitions, revision snapshots, personal templates, occurrences and attempts have separate stable IDs. Serialize concurrent writers with a per-user lock, atomically replace private state, recover interrupted writes. Scheduled IDs derive from job and due instant; manual IDs are independent. Persist a claim before side effects. Edit affects future runs; archive suppresses future occurrences and retains history. Bound catch-up to the latest eligible occurrence. Time zone is IANA, weekly day is explicit, cron is five fields. Document DST gaps and repeats and validate with a fake clock.
3. **Launch and supervision.** Reuse native Swarm launch and session identities. Never parse user prompts as shell. Create a fresh session per occurrence. Ensure workspace permission is selected and supported by every route. Concurrent occurrences use independent Git worktrees; refuse unsafe overlap. Keep unfinished work. Record dispatch intent, reconcile uncertain acknowledgement, and block duplicate launches. Admission failure advances the ordered agent list. Mid-run exhaustion requires verified stop before continuation in the same workspace, with bounded evidence-based handoff, durable attempts and preserved previous artifacts. Unknown outcomes require human attention.
4. **Completion and board.** The worker leaves a concise closing chat message describing result, current state and links, then invokes a run-scoped completion verb. Verify session identity and active attempt, persist idempotently. The finishing session owns the automation tag and left marker. Open directly into its native final chat; changing/removing the tag clears the marker while history persists. Failed or vanished workers surface actionable status. Never equate process exit with completed work.
5. **CLI and timer.** Shared store and validation API for CLI and terminal UI. CRUD, pause/resume/archive, history, run-now, status, tick, complete, personal templates. The timer carries only a command and host-local user context. Install one launchd LaunchAgent or systemd user timer with rollback, health and uninstall. Keep machine sleep behavior user-selectable. Test two ticks and interrupted launch; run-now never consumes the calendar occurrence.
6. **Terminal UX.** Match board spacing, keyboard and mouse controls. Implement list, detail, create/edit, template save/use, agent ordering, workspace/authority, review, history and attach. Distinguish missed/paused, queued/working, needs input, incomplete, exhausted and ready. Keep status readable at small widths. Use the real board and launch pathways in integration tests.
7. **Qualification and release.** Sol and Astra independently review the plan. Reconcile objections before implementation. Sol owns difficult lifecycle work; Luna owns bounded supporting tasks where available. Astra reviews final code and tests. Test package/race suites, build, vet, lint, timer smoke and real end-to-end scheduling on both hosts. Verify zero cross-job completions, false-success receipts, duplicate workers and lost work under restart. Merge only when evidence passes; derive next minor from current remote release, publish via existing signed/tag workflow, monitor CI and release, verify installed versions and smoke run. Preserve a rollback path that retains schedules/worktrees.

## Review decisions and host evidence
Sol and Astra independently reviewed the launch and lifecycle contracts against ac613c2c. An occurrence persists a separately generated operation ULID and canonical request hash. Check OwnerLaunchReplay and durable session evidence after interrupted dispatch or prompt delivery. An unknown acknowledgement freezes that attempt. A shim exit receipt, including backend wait and process-group cleanup, qualifies stop; a kill request or missing PID alone does not. Use occurrence-owned workspace paths across fallback. Prevent competing automatic auth replacement. An active-attempt capability authorizes completion and expires on handoff. Persist completion before projecting the marker; retry the projection independently. Qualify the real native execution route and the actual permission flags for each adapter. Ambiguous exhaustion and unsupported authority require actionable attention.
Mac arm64 and tf_nathan Linux x86_64 each passed a private two-worktree write-isolation probe and a user-service payload test (launchctl submit / systemd transient timer). Same-worktree progress was readable after simulated handoff. These probes establish host mechanics only. Real agent and recovery gates remain separate. Native Swarm versions observed were 0.13.29 locally and 0.27.0 on the VM; latest published release 0.27.0, requested minor target 0.28.0. Linux root filesystem is almost full; stage qualification binaries on an available executable volume, and verify persistent capacity before release activation.

### Second review iteration
Astra's implementation review found two release-blocking host issues. First, a restricted coding agent needs an attempt-scoped completion channel: granting access to the supervisor's owner socket would grant unrelated capabilities, while some sandbox modes deny that socket outright. Qualify a narrowly scoped native tool alongside the CLI receipt. Verify refused unrelated operations and verify completion from inside each advertised sandbox. Second, a cold Linux timer must prove daemon and worker survival after the systemd oneshot exits. A detached terminal session alone does not move a process out of its service cgroup. Qualify cold and warm starts independently using the user's saved environment. The supervisor must not replace its saved environment with the timer's sparse environment.

Other required regressions include a lost manual-run reply and deliberate retry with the same invocation ID, a delayed occurrence racing a revision edit, forward then backward clock movement, actual evidence in the replacement worker's handoff, a worker still live after its completion receipt, and an uncertain attempt that later gains affirmative session or containment evidence. Use indexes for actionable occurrences and outstanding board projections so retained history does not dominate each timer tick. Verification should include at least a thousand historical runs.

The Linux host accepted a live, read-only Codex invocation under the user account. Its noninteractive shell omits the user agent executable directory. Record successful scheduler-driven execution separately from this provider preflight.

### Settled implementation

| Surface | Ownership and behavior |
| --- | --- |
| Terminal | Board → More → Automations lists this host's jobs. The directory shortcut opens the same form. Review shows the resolved directory, authority, ordered agents and local trigger times. A personal template copies text into an editable draft. |
| Host timer | A single launchd calendar or systemd user timer ticks once a minute. Pin the installer's state and socket paths. For cold starts, reload the supervisor's private saved environment. Jobs retain their own missed-run policy. |
| Store | A private bbolt database in the supervisor's schedules directory stores jobs, immutable revisions, occurrences, attempts and receipts. Calendar claims use job plus UTC instant. Manual claims bind a caller-generated operation ID to one job. Index pending work separately from retained history. |
| Supervisor | Claim before creating a workspace. Verify native workspace ownership at launch. Gate scheduled shim execution until process identity is durably recorded. Persist prompt delivery intent before writing to the native conversation. Preserve an ambiguous attempt for inspection. |
| Fallback | Advance through the configured agent order after affirmative refusal or supported exhaustion with verified process containment. Carry a bounded handoff and the same occurrence workspace. Parallel occurrences have separate worktrees. |
| Completion | The worker submits an attempt-bound receipt over a completion-only endpoint. Verify the closing assistant item in the finishing conversation and retry projection when the session comes back. Opening the finishing chat keeps the receipt. Changing its automation tag clears the review marker. |
| Release | Run local and VM canaries with disposable state, run the repository gates, merge the reviewed commit, then use the existing signed release workflow. The previous published release is v0.27.0. |
