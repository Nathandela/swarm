# Codex account-switch recovery review

## Observed failure

The installed Codex 0.154.0 rejected three attempts to resume the same Gaston
conversation with `Permission overrides are not supported when resuming a remote
task`. Swarm had supplied both `--sandbox workspace-write` and its network
permission override, then attached the TUI to its own local app-server using
`--remote unix://...`. This error does not establish that the thread is cloud-hosted.
The old auth watcher recorded launch as recovery and deleted the source before
the replacement exited. Manual retries retained a separate board row per attempt.

## Provider characterization

The exact release source establishes the difference from older supported Codex:

- [0.154.0 startup rejection](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/tui/src/app/startup.rs)
- [0.154.0 permission override detection](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/tui/src/app/config_persistence.rs)
- [0.154.0 remote resume restores saved server permissions](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/tui/src/app_server_session.rs)
- [0.147.0 earlier behavior](https://github.com/openai/codex/blob/rust-v0.147.0/codex-rs/tui/src/app_server_session.rs)

Only a live backend handshake identifying 0.154.0 selects alternate TUI resume
arguments. The original executable, fresh-launch flags, uncharacterized versions,
and standalone fallback are preserved. Explicit sandbox overrides on Codex resume
are refused because restoring saved permissions cannot honor a requested change.

## Implementation and independent review

Three agents implemented/reviewed provider compatibility, auth lifecycle, and
roster presentation; cross-review covered the other agents' changes. Findings
fixed before final validation include lifecycle/resume lock inversion, conflicting
thread IDs being hidden, archived discussions resurrecting after crashes, deleting
a checkout still used by a replacement, exact-ID CLI lookup regressions, and
foreign credential stores causing repeated recycling.

The watcher retains source history, persists one candidate, and observes a live
matching subscribed backend before logging transport readiness. Failed/absent
candidates and a two-minute readiness timeout end automatic retries. Archived
sources cancel owed recovery. Source environment, tag, lineage and the actual
Codex/worktree directory survive resume. Safe input/controller deferral remains.

The desktop TUI and `swarm ls` project explicit resume lineage to its current
attempt. Raw protocol lists and events retain exact IDs for watch/control/history.
Deleting the visible final attempt archives predecessors rather than resurrecting
or deleting their history; deleting retained interior history is refused. Multiple
live actors and conflicting conversation identities remain visible.

## Validation status

Before upstream integration: focused adapter/shim/daemon/persist/protocol/TUI/
skeleton/CLI recovery checks passed; golangci-lint reported zero issues; the strict
Phase B manifest checker passed. After rebasing onto main `37336d34`,
`go build ./...`, golangci-lint (zero issues), the strict manifest checker, and
focused race checks for skeleton/persist/protocol recovery and discussion lifecycle
all passed. The full `go test -p 2 ./...` suite also passed, including subprocess
integration and mobile Go packages. The owner subsequently authorized merging to main and publishing the next patch
release, v0.13.32. The release workflow runs its full gates before publication.
An initial long TMPDIR contaminated source-scanning/UI tests, inherited SWARM hook
environment affected hook tests, and low disk correctly tripped the relay's 1 GiB
admission floor. Corrected test setup uses short /tmp paths, clears SWARM_* for test
processes only, and leaves normal disk safeguards enabled. No production behavior
was changed to bypass those safeguards.

## Acceptance boundaries

No production session, credentials, daemon, or release was changed. Two-account
live acceptance and recovery of the historical missing-source-rollout condition
remain unverified. A successful transport subscription is not proof of a successful
authenticated model turn. No message with potentially executed tools is replayed.

An actively controlled session, busy turn, approval, unresolved write, or unknown
credential store still defers automatic recycling. Same-account re-login still
requires `swarm relogin --force`. Custom CODEX_HOME and foreign HOME stores are held.
The phone's durable journal/reducer and older desktop clients do not consume the
new board projection; this change does not claim phone row consolidation or live
controller migration. The underlying process/session ID changes on resume.

Tracked acceptance follow-ups: `swarm-n21` (controlled two-account canary) and
`swarm-43h` (phone journal presentation).
