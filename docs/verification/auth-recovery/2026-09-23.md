# Codex 0.156.1 remote resume

## Failure and fix

Eight local resume attempts on 2026-09-23 exited with `Permission overrides are
not supported when resuming a remote task`. Swarm 0.13.33 selected its cleaned
remote resume arguments only for the live backend version 0.154.0. The installed
Codex was 0.156.1, so Swarm still attached with permission overrides.

The fix adds the characterized 0.156.1 version and passes a recorded source
sandbox mode to the per-session app-server as its `sandbox_mode` default.
Removing the TUI flags alone is insufficient: legacy threads without a named
permission profile use the server defaults on cold resume. Fresh launches and
standalone fallback remain unchanged; model/config argument values are not
mistaken for flags. Only the three supported sandbox modes become defaults.

## Native runtime characterization

Isolated temporary Codex homes and genuine completed no-tool turns were used;
production discussions and the Swarm daemon were not restarted. The actual TUI
rejected either `--sandbox workspace-write` or the network config override on
remote resume. With both removed, it opened the discussion but the default
server changed a legacy workspace-write thread to read-only/network restricted.

Native cold-resume RPC checks on Codex 0.156.1 established:

| Saved thread | Server fallback | Resumed policy |
| --- | --- | --- |
| Legacy workspace-write, network enabled | Default read-only | Read-only, network disabled (reproduces policy drift) |
| Legacy workspace-write, network enabled | Workspace-write, network enabled | Workspace-write, network enabled; on-request approval retained |
| Named `:workspace`, network disabled | Workspace-write, network enabled | Workspace-write, network disabled; named profile retained |
| Named `:read-only`, network disabled | Workspace-write, network enabled | Read-only, network disabled; named profile retained |

The two tested built-in named profiles take precedence over the fallback; the fix
does not widen those profiles. Threads without a saved profile or a recorded Swarm launch
sandbox (including external imports) retain Codex's native current-config
fallback. This is not a claim to reconstruct historical legacy policy that
neither provider nor Swarm recorded as a restorable profile.

## TDD and review

`TestBackendResumeCommandArgsRequiresCharacterizedRunningVersion` failed for
0.156.1 before the gate change and passed afterward. The adapter regression then
failed for all three sandbox modes before the backend-default change and passed
afterward. Coverage includes unchanged standalone/fresh arguments and a model
value that looks like `--sandbox`. Three Sol subagents handled implementation,
provider characterization, and independent review; the native probe caught the
policy drift before release.

The corrected actual remote TUI also retained filesystem write access and network
enabled in its `thread_settings_applied` event. A subsequent authenticated no-tool
turn completed, and both turns recorded workspace-write/network enabled.
The probe used loopback WebSocket because this host's existing Codex daemon
socket directory was mode 000; it exercises the same remote TUI path. A live
Swarm Unix-socket attach, legacy danger-full-access, and custom named profiles
were not runtime-tested. Adapter tests cover command composition for all three
sandbox modes. Build, vet, pinned golangci-lint (zero issues), strict Phase B
manifest checks, and focused race tests passed locally.
