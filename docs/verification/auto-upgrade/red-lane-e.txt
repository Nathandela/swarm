Reading of the red run, case by case
--------------------------------------------------------------------------------

case1  exit 0 with an EMPTY stderr: the plain restart ran and reported nothing, so
       neither "converged" nor "restarted from the saved environment" is present. The
       replacement was spawned from the launchd-like caller environment, which is the
       defect L2 exists to prevent.
case2  skipped, because case 1 never converged the daemon and there is nothing for a
       second run to be idempotent about.
case3  exit 0 against a daemon with a LIVE fake session: rule 2 does not exist, so the
       session was interrupted rather than the converge deferred (want exit 2).
case4  exit 0 with daemon.env deleted: rule 3 does not exist, so the daemon was restarted
       from the timer's own bare environment instead of being refused (want exit 3).
case5  exit 0 but with no reason line, and a daemon SPAWNED into an empty state dir:
       rule 0 does not exist (want exit 0, "no daemon holds the lock", nothing spawned).
case6  `daemon restart --bogus` exit 0: the unknown argument was swallowed and the daemon
       was restarted (want exit 2 and the usage line).

--------------------------------------------------------------------------------
One test bug fixed BEFORE the implementation was written (TDD phase 2)
--------------------------------------------------------------------------------

The first draft of case 3 polled the on-disk roster for the id `Client.Launch` returns.
That id is federation-namespaced ("<endpoint>/<local>", protocol.NamespacedID), while the
persisted meta.json — the roster the converge's rule 2 reads — carries the LOCAL id, so
the poll could never match and the case failed with "never appeared busy" instead of on
the missing wiring. The test now derives the local id and asserts on that, which is also
the id the deferral line names.
