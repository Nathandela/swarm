# OpenCode implementation evidence — 2026-10-18

Implementation is active under `agents-tracker-vyhy`. This record covers accepted changes and measured contracts; it does not certify the full maturity plan or a release. Installed Swarm remains unchanged.

The implementation workers run through an isolated Swarm daemon in separate Git worktrees. Current workers use **`opencode/deepseek-v4.1-flash-free`** and **`opencode/glm-5.3-flash-free`**, with the native catalogue's supported `reasoningEffort: max` option. Native message records verify the provider/model identities and report zero model cost. GLM reviews DeepSeek changes and DeepSeek reviews GLM changes; independent Astra reviews and supervisor tests determine integration. A lifecycle prototype written before failing tests was rejected and preserved separately; its replacement began from the clean baseline with a test-only commit.

## Native contracts measured

The non-generating OpenCode 1.19.3 creation probe verifies correct versus absent/wrong Basic authentication, caller-owned session IDs, explicit model/agent/variant binding, and legacy reads of the created row. Changed create arguments return the original binding and require validation. Unset model/agent remain absent even with a native configured default; creation alone does not prove the attached TUI's first prompt selection. A create request whose response was discarded is recovered by exact ID. Restart validation reads the original session and creation timestamp **before** any create retry, so recreation cannot masquerade as recovery. [Native creation results](opencode-implementation-2026-10-18/creation-contracts.json).

An independent Astra test of a frozen, uncommitted HTTP client snapshot passed against the real isolated 1.19.3 server without model calls. It covers authentication, caller-ID create/retry, binding mismatch refusal, legacy reads, SSE subscription before create, native child creation/events, empty status/request/history reads, cancellation, and exact session/child persistence across restart. This initial smoke does not qualify populated history, request decisions, generation, process ownership, or the final changing client revision. [Initial native client run](opencode-implementation-2026-10-18/http-native-client-initial.txt).

Review found concrete client defects requiring further test-first corrections: ambiguous write errors treated as definite rejection; malformed `null` snapshots treated as empty; native opaque history cursors rejected; foreign direct-child rows accepted; and permission/question/history fields lost through display-oriented structs. These are not accepted as production-ready behavior. A populated-history qualification uses native `noReply` append calls only after pinned source establishes that they return before model, title and compaction execution.

The live supervision run also confirmed that a successful terminal `send` during busy work is not a native prompt receipt. A review instruction was absent from native history and was re-delivered while idle, then verified by its exact native message ID. The semantic route must retain separate delivery, admission and correlated outcome states.

## Qualification limits

The full macOS baseline predating these changes fails existing Linux-managed-account fixtures, platform-specific reachability checks, and an installed x86 gobind binary on this ARM host. This is tracked by `agents-tracker-vyhy.10`. Linux qualification runs in an isolated ordinary-user container with pinned Go/mobile tools and private source/cache storage; fixture failures caused by a root container or missing Git/tool setup are not application regressions.

The owned backend, native state/projection, TUI bridge and continuity changes remain under implementation and review. Full repository race/release gates, populated request/child composition, mixed-harness fault tests, and actual 1h/24h/72h workloads must pass before their corresponding maturity claims. No short smoke test substitutes for elapsed sustained qualification.
