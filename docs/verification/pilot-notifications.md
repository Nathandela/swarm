# Pilot watch verification

`swarm pilot --context <path> watch <id>... [--after <cursor>]` exposes the daemon's atomic journal snapshot and live records as line-delimited JSON. It filters records to explicit discussion IDs and emits only terminal replies, requests for input, review-ready/completed state, exits, losses, and structured gaps. Each line keeps worker data separate from trusted pilot guidance. The caller can resume after its last consumed snapshot or event cursor; a replay snapshot retains the requested cursor while `boundary_cursor` reports the journal head. A full resync emits `history_gap`, and stream loss emits `disconnected` with a nonzero exit. Pilot exit cancels its watches.

Focused tests: `TestPilotWatchSnapshotFiltersWorkersAndOnlyWakesOnCompletedReply`, `TestPilotWatchReplayAndFullResyncAreExplicit`, `TestPilotWatchRelevantWakesOnTerminalResultsAndInput`, `TestPilotWatchExitUnblocksFullStdoutPipe`, and the `TestClientJournalSubscribeFrom*` protocol tests exercise filtering, replay, atomic snapshot plus live delivery, large records, capability refusal, cancellation, and bounded-reader failure. The isolated CLI gate `go test ./cmd/swarm -run '^TestPilotRealCLIControlsTwoWorkersWithoutChangingOrdinaryCLI$' -count=1 -timeout180s` passed in 1.606 seconds (`/tmp/swarm-pilot-watch-e2e.log`): two independent pilot contexts watched separate fake workers; exiting one context closed only its watcher, while the second received its worker's exit record. The earlier failed run caught the public discussion ID versus local journal ID mismatch; the passing run uses validated public IDs and normalizes journal records back to them.

Final local gates passed: `go test ./...` (`/tmp/swarm-pilot-tests.log`), `go build ./...`, `go vet ./...`, `golangci-lint run` (zero issues), and focused repeated `-race` tests for `cmd/swarm` and `internal/protocol` (`/tmp/swarm-pilot-final-*.log`). These are local implementation gates; they do not establish delivery into an existing host conversation.

An isolated Codex 0.156.1 stdio probe established that `turn/start` with `input: []` and a `toolOutput` entry carrying `name` and `output` can wake an idle thread, emit a function-call output, and complete with a model acknowledgment. The busy-turn probe accepted the same input in the active turn. The interrupt probe observed no further new turns for five seconds. These probes establish the input shape and observed behavior in that scratch thread; they do not establish durable registration to this caller, routing from Swarm's watch into the existing host's stdio connection, or Stop queue revocation.

The shipped watch is a pull stream. It does not itself schedule the idle assistant or deliver tool output into an existing Codex host conversation. No host-owned registration interface is available in this repository; thread IDs, process identity, environment, and working directory are insufficient proof of the caller conversation.
