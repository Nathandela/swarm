--------------------------------------------------------------------------------
DIAGNOSIS
--------------------------------------------------------------------------------

The test claims to prove PB-BIND-6's drop-oldest overflow contract (mobile/events.go:42-53,
58-72): flood the journal past CallbackQueueSize while the listener is wedged, then assert
an overflow gets surfaced and the delivered count stays bounded.

It is miswired and passes for the wrong reason:

1. The flood at robustness_test.go:177-181 calls h.PushEvent with
   Type: "group_transition" -- journal-family records that are gated by App.subscribed
   (mobile/relay.go:770-773 for onJournal, :800-803 for onInteraction). The test never
   calls App.SubscribeJournal (mobile/app.go:1011) to turn that gate on; it only calls
   h.App.TerminalWatch(testSession) at :184, an unrelated action. The flood only reaches
   the dispatcher because NewApp seeds subscribed: true by default (mobile/app.go:193).
   The test is exercising that default, not the subscribe/gate wiring PB-BIND-6 depends
   on for a real client (a client that has NOT subscribed).

2. The upper-bound assertion at robustness_test.go:194,
       if got := l.seen(); got > swarmmobile.CallbackQueueSize+emitted { ... }
   compares against CallbackQueueSize + emitted = 256 + 512 = 768. But drop-oldest can
   only ever REMOVE items from the queue before delivery (events.go:42-53) or COLLAPSE
   consecutive drops into a single "overflow" marker event (events.go:58-72) -- neither
   path can inflate the delivered count above roughly emitted + 1 (the one collapsed
   overflow marker), i.e. ~513. The stated bound (768) is unreachable by construction:
   this assertion can never fail, on a correct implementation or a broken one.

--------------------------------------------------------------------------------
CONCLUSION
--------------------------------------------------------------------------------

TestPBBIND6_SlowCallbackDoesNotStallTheCoreAndOverflowIsObservable does not verify
PB-BIND-6's drop-oldest/overflow-surfaced contract against the wiring a real subscribed
client would use. It passes only because NewApp defaults subscribed to true and the test
never subscribes or unsubscribes; and even when events do flow, its upper bound
(CallbackQueueSize + emitted = 768) is unreachable by construction (max ~513 deliverable),
so it could never catch an unbounded-delivery regression either. This corroborates
docs/verification/remote-phaseB-traceability.md:108 ("PB-BIND-6 NOT MET -- drop-oldest
stated in three places, enforced by none").

This is a diagnosis only. The test itself was not modified as part of this run; git diff
on mobile/app.go and mobile/conformance/robustness_test.go is clean.

MUTATION CONTROL (2026-08-14, GREEN/implementer role)
--------------------------------------------------------------------------------

The test was rewired in mobile/conformance/robustness_test.go:
  - it now calls h.App.SubscribeJournal() before the flood, exercising the real gate
    instead of NewApp's subscribed-by-default value;
  - it waits (via ReadJournal/NextCursor) for the WHOLE flood to have reached the
    dispatcher's queue before releasing the blocked listener, so drop-oldest's cap has
    already been fully applied and delivery below is not racing the tail of the flood
    still arriving;
  - the unreachable upper bound (CallbackQueueSize+emitted = 768) was replaced with
    survivor assertions: dropped() > 0, delivered journal count <= CallbackQueueSize+1,
    and a cursor-based old/new-half split (at most one surviving cursor may fall at or
    below the flood's midpoint, and at least one must fall above it) -- i.e. drop-oldest
    must retain the newest half and evict the oldest half, not the reverse.

To prove those survivor assertions actually pin the drop-oldest CONTRACT (and are not
themselves vacuous), mobile/events.go's dispatcher.emit was hand-mutated from drop-OLDEST
to drop-NEWEST (discard the incoming event once the queue is at CallbackQueueSize, instead
of evicting the queue's head):

  --- a/mobile/events.go
  +++ b/mobile/events.go
  @@ func (d *dispatcher) emit(e *Event) {
   	d.mu.Lock()
  -	if len(d.queue) >= CallbackQueueSize {
  -		d.queue = d.queue[1:]
  -		d.dropped++
  -	}
  -	d.queue = append(d.queue, e)
  +	if len(d.queue) >= CallbackQueueSize {
  +		d.dropped++
  +		d.mu.Unlock()
  +		return
  +	}
  +	d.queue = append(d.queue, e)
   	d.mu.Unlock()

Under drop-newest, the queue fills with the OLDEST ~256 cursors of the flood and every
later push (including the final, newest cursor) is discarded on arrival, so the newest
cursor is never delivered -- exactly the survivor property the rewritten test pins. The
mutation was then reverted; `git diff mobile/events.go` is empty, confirmed clean.
