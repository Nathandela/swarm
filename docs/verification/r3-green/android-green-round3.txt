2. THE FIXES (file:line, minimum surface, no assertion weakened)

A. BLOCKING - WakeDrops never reached disk in the FCM topology:
  internal/phonecore/pushbinding.go:541 (countWakeDropLocked) -- the
    FIRST refused wake of a process persists the container once; later
    refusals are in-memory-first and ride the next real state change.
    Durable in the wake-drop-die process, cost capped at ONE re-seal +
    fsync per process lifetime (an attacker already pays a process
    spawn per unverifiable message).
  internal/phonecore/core.go:84 -- the per-process latch
    (wakeDropPersisted, guarded by mu); persist failure leaves it unset
    so the next refusal retries, and never changes the verdict.

B. BLOCKING - rotation ordering could install a stale token durably:
  internal/phonecore/pushbinding.go:326 -- the seam CHANGES SHAPE:
    EnsurePushRegistration now takes a TokenSource and reads the
    CURRENT token INSIDE regMu, at act time. Rationale recorded on the
    type: two opaque token strings cannot be ordered by any phone-side
    rule, so any snapshot taken before the lock can be installed by a
    caller that merely acted later than it read. Android callers hold
    exactly this source (FirebaseMessaging.getToken answers the
    current token; onNewToken's argument is only the change hint).
  internal/phonecore/pushbinding.go:110,434 -- LastFCMToken persisted
    beside InstallationID on every accepted register/rotate;
    Core.PushFCMToken() makes staleness detectable at the seam.
  internal/phonecore/core.go:77 -- regMu comment extended with the
    read-inside-the-lock rule.
  Probe as permanent test: r3ar3_tokenrecency_test.go
    (..._AQueuedCallCannotInstallAStaleToken) holds caller A's PUT
    mid-flight with a held transport, rotates the source, queues caller
    B, and asserts the wire ENDS on the newest token, the durable
    record follows it, and the REAL pushgw forwards a subsequent wake
    to the newest token.
  MECHANICAL FALLOUT, disclosed: the five pre-existing call sites in
    r3a_installation_test.go (4) and r3ar2_review_test.go (1) now wrap
    their literal in staticToken(...). Single-line regex edit, zero

    line counts are unchanged).
