---- design decision this RED run pins, recorded here rather than only in code comments ----

The spec's own header (push-gateway-api.md Precedence clause) leaves one thing open:
whether a non-2xx wake-submit refusal is unconditionally retryable (ADR-015 P9's literal
text) or terminates the obligation for the specific refusals section 6.4 marks
`retryable=false` (the spec's own `abandoned` state, itself an unresolved divergence per
its §14.1 row 7 / §13.8). This task's instructions are explicit that the RED suite must
pin the THREE-WAY mapping (retryable / abandoned / terminal) section 6.4 already states,
so wakesubmitter_test.go's TestWakeObligation_SubmitOutcomeMapping tests the FULL table --
`ObligationAbandoned` is a real terminal state in this suite's contract, not something
left to a future ruling. obligation_test.go's file header records this choice explicitly
so a reader of the code, not only of this evidence file, sees the same note.

---- addendum, 2026-08-15: PG-OBL-2 deferred-wake residual (R3 punch-list review) ----

The GREEN implementation that followed this RED run (agents-tracker-hggx.4.2, PG-OBL-2:
obligation append must precede mailbox publish for gateway-transport pairings) closed the
crash gap for every IMMEDIATE wake, but a narrower instance of the same gap survives by
design in the DEFERRED path (ADR-010 section 4(b)). PushNotifier.wouldWakeNow
(internal/remotegw/push.go) deliberately reports false for a window-suppressed
interaction wake, so preAppendObligation records no durable obligation for it: the
mailbox record is published immediately and the obligation is appended only when the
single deferral timer fires, up to 30s later, via maybeWake's send(). A crash inside that
window publishes an event with no durable obligation announcing it -- literally PG-OBL-2's
original "a crash in that gap publishes an event the phone is never told about," just
narrower than the case that was fixed.

This is not an oversight: pre-appending an obligation at trigger time for the deferred
case would durably record intent to send a wake this process has not committed to, since
the timer re-reads the push preference AT SEND (PB-PUSH-8) and may decide not to send at
all. Trading the crash-window gap for a false-obligation risk on every preference flip
was judged the worse trade. It is nonetheless a real, accepted deviation from PG-OBL-2's
"before or atomically with" requirement, not a closed gap, and is tracked as a distinct
follow-up: bd issue agents-tracker-hggx.4.4.
