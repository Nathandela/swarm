1. D0 -- THE RESET MARKER (RED, then GREEN)

  The defect, from the reviewer's probe: the phone holds {epoch 1, rev 40, "OLD screen"}; a
  RESTARTED daemon's first loop sends {epoch 1, rev 1, Reset:TRUE, "NEW screen"} -- because
  viewEpochSeq is a bare process-global atomic that starts again at zero in every daemon
  process -- and SnapshotCache.Apply compares only (epoch, revision), so the reset frame AND
  the 39 revisions after it are dropped. The user reads a plausible, frozen, pre-restart
  terminal. Sessions surviving a daemon crash/restart/upgrade is a DESIGNED property of this
  system, so this is not an edge case.

  test written first: internal/phonecore/r8r5_viewreset_test.go

2. F6-2 -- THE BLANK AND THE LAPSE DETECTOR (RED, then GREEN)

  The defect: TerminalWatcher.Reap -> blank() -> Gateway.BlankTerminal sends
  TerminalViewV1{Session: session} -- RenderedAt is the ZERO TIME. The phone reads zero as
  UNKNOWN by ruling (ADR-017 C4), ageOf(0) = 0, and watchLapsed(0) is FALSE, so
  PhoneSurface.reconcileTerminalWatch took its renewHeldWatch() early return FOREVER. Round 3's
  blank actively defeated round 4's detector, and no test drove the two together.

  THE PROPERTY SPANS THE GOMOBILE BOUNDARY, so it is held by three tests that meet at one set
  of values, and that seam is stated rather than papered over:

    (a) internal/remotegw/r8r5_reapblank_test.go -- the machine really sends those values, over
        a real protocol.ServeRemote + a real remotegw.Gateway + the real TerminalWatcher
        (Reap -> blank -> sink). It also asserts NON-VACUITY: a LIVE view carries cols/rows.
    (b) internal/phonecore/r8r5_viewreset_test.go -- they survive the phone's real cache.
    (c) android/.../TerminalFallbackWatchTest.kt -- the rule that READS them answers LAPSED.

  (c) is the failing-first one; the production rule it needs did not exist when it was written.
  Its RED run is the MUT-E transcript in closing2-mutations.txt (the production line reverted to
  the age-only rule it had before this round), because a Gradle run is the only way to execute
  it: 6 tests, exactly the 2 blank-shaped assertions FAILED, the other 4 passed.

  production change:
    android/.../ui/screens/TerminalFallbackScreen.kt -- TerminalGrid.machineStoppedRendering
      (the machine's blank is identified by its GEOMETRY, never by its age: stamping a render
      time on a blank would make the blank look FRESH, the same disagreement sign-flipped) and
      TerminalFallbackBinding.watchLapsed(grid) = blank OR aged-past-horizon.
    android/.../PhoneSurface.kt -- heldWatchLapsed asks about the GRID, not about .ageMs.

  A snapshot that never arrived is a facade REFUSAL and not a blank, so the arrival window is
  still "not lapsed" and no redraw tears down a peek that is still opening.

4. WHAT THIS ROUND DID NOT DO

  - The parked control half was NOT built. No terminal_input sink, no generation/keepalive
    plane, no take-control affordance. ADR-017 C0/C1 stand unchanged.
  - viewEpochSeq was NOT made durable across daemon restarts. Reading `reset` is the guarantee
    the protocol already carries and it closes the defect; persisting the counter would be a
    second way to say the same thing.
  - No new UI copy for a blanked screen. The blank is now transient (the screen re-watches), and
    a sentence about it would be new product surface, not a fix. Noted as follow-up.
