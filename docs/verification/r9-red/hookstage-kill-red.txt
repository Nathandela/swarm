FIRST OUTCOME (test as first written): NOT CAUGHT -- the matrix passed.
Root cause: delivery labels came from scriptedCapture's order-consuming script
(one batch per Interactions call), so a doubled apply SHIFTED the labels onto
the extra calls instead of duplicating any label; every label still appeared
exactly once. The test was STRENGTHENED in response (no assertion weakened):
each post now carries its (kill point, stage) label IN the callback's Raw body
(ADR-010 s6 carriage, verbatim through spool and drain) and a new
echoCaptureAdapter shapes exactly one agent_message per record from that
carried label -- attribution per RECORD, not per capture order. A redelivery
in a fresh incarnation re-shapes the SAME label under a fresh item_id, so it
lands in the journal and trips the per-stage exactly-once count.
