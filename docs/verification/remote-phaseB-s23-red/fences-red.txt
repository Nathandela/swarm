defects were closed and the CLASS was not:

  metric fence (s23_kit_test.go:905) required an UPPERCASE name, a lowercase `f` suffix and
  end-of-line immediately after it, so each of these carried a dp literal into the kit with
  no `origin:` annotation and no complaint:

      const val PROBE_DP = 7F             (capital suffix)
      const val X = 7f // trailing comment (anchored \s*$ never matched)
      @JvmField val PROBE2_DP = 7f        (annotation prefix)

  animator fence (s23_motion_test.go:60) listed six identifiers, so these constructed an
  animation that never passes Motion.duration() and walked straight through:
      AnimatorInflater.loadAnimator(ctx, id).start()
      SpringAnimation(view, DynamicAnimation.ALPHA).start()

  PB-DS-8's text is that NO animator is constructed outside the kit. Six strings is not that.

All four PASSED before the widening -- that is what made them findings. Badge.kt restored
after each; `git diff` empty.

WHAT IS STILL FAIL-OPEN, STATED RATHER THAN CLAIMED CLOSED. Both fences remain DENYLISTS,
and a denylist's failure mode is always "a form nobody listed". A metric written as an Int
(`val dot = 7`), assembled (`7f * 1f`), or read from a companion is still invisible; an
animation driven through an API not in the list still passes. The honest structural answer
is an allowlist of PERMITTED constructs, which is a larger change than this fix and would
have to be designed rather than patched. Recorded so the next reader does not mistake a
wider denylist for a closed class.
