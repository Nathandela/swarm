contain a double hyphen"); this one is `swarm_nav_back.xml`, written by a different agent in the
same slice, with the same cause and no gate in between.

## Why no existing gate saw it

Every check over `res/` in `android/gate/` reads those files as text: it greps for a token name, a
stroke width, a colour reference. `s23_kit_test.go` reads this very drawable -- it recomputes the
chevron's stroke weight from the design row and compares it to `android:strokeWidth` -- and it read
the file successfully, because a regular expression over a byte slice does not care whether the
document parses. Fifteen resource files were being checked in detail by a package that could not
tell whether any of them was XML.
