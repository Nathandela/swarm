# External Claude Agent View reattach

`swarm reattach --cli claude` inventories native `claude agents --json` background sessions. `--dry-run` only inventories and `--all` includes settled sessions. A live source requires `--take-over`, which runs the pinned native supervisor's `claude daemon stop --any` before acquiring any session. Swarm checks the selected transcript and profile before invoking takeover. The owner independently requires an exact settled Agent View row, checkout, transcript and authority. The shim repeats the check immediately before invoking native `--resume`; native hooks confirm the original conversation identity.

Installed Claude Code 2.1.329 on Linux passed the isolated `claude_native_linux.sh <staging> <installed-claude> rust_claude_resume.py external` fixture. A real background worker got a synthetic loopback answer and remained live. Dry-run, CLI without takeover, and a direct owner request could not acquire it. Explicit takeover settled the native source, created one Swarm row for the same native conversation, and rendered its old answer without replaying the original user turn. A duplicate was refused and no fixture processes survived.

macOS Clippy passed. The native macOS background witness remains open. The protected fixture stopped an attempted creation of `/tmp/cc-daemon-501` by the installed Claude background bootstrap. The installed user's namespace and native login stayed untouched. [Pinned Go Agent View command and acquisition sequence](../../cmd/swarm/reattach.go)

Before a native stop, the Rust caller requires a Claude-specific read-only owner preflight for every selected conversation. The original full Go owner is recognized through its owner-only context-guard read in addition to general external-resume negotiation. An older Rust owner that only shares the Codex external-resume capability cannot proceed to a Claude takeover. Duplicate native background UUIDs or a changed normalized inventory refuse takeover. The provider does not expose an atomic compare-and-stop operation, so the client re-reads the inventory immediately before stopping and the owner and shim independently recheck settled custody during adoption.

The takeover compatibility witness exercised the Rust client against the new Rust owner, the prior Rust external-resume-only hello contract, and the original full Go owner. With installed 2.1.329, an unsupported owner, duplicate UUIDs, and a background inventory mutation during the new Rust preflight left the live native source running. The duplicate and mutation fixtures also detected any attempted native stop. Positively qualified Rust and Go owners each acquired a separate disposable source through the public CLI, preserved the prior answer and did not replay the prompt, with zero surviving fixture processes.
