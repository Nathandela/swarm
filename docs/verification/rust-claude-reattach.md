# External Claude Agent View reattach

`swarm reattach --cli claude` inventories native `claude agents --json` background sessions. `--dry-run` only inventories and `--all` includes settled sessions. A live source requires `--take-over`, which asks the compatible owner to run the pinned native supervisor's `claude daemon stop --any` before acquiring any session. Swarm checks the selected transcript and profile before invoking takeover. The owner independently requires an exact settled Agent View row, checkout, transcript and authority. The shim repeats the check immediately before invoking native `--resume`; native hooks confirm the original conversation identity.

Installed Claude Code 2.1.329 on Linux passed the isolated `claude_native_linux.sh <staging> <installed-claude> rust_claude_resume.py external` fixture. A real background worker got a synthetic loopback answer and remained live. Dry-run, CLI without takeover, and a direct owner request could not acquire it. Explicit takeover settled the native source, created one Swarm row for the same native conversation, and rendered its old answer without replaying the original user turn. A duplicate was refused and no fixture processes survived.

macOS Clippy passed. The native macOS background witness remains open. The protected fixture stopped an attempted creation of `/tmp/cc-daemon-501` by the installed Claude background bootstrap. The installed user's namespace and native login stayed untouched. [Pinned Go Agent View command and acquisition sequence](../../cmd/swarm/reattach.go)

For a live batch, the Rust owner holds its launch gate from whole-batch capacity admission through the native stop and every Swarm reservation. A lost row still occupies capacity for this check because it can recover during admission. The owner checks native inventory, executable, account and checkout immediately before stopping, then validates settled custody as it reserves each row. It returns per-conversation outcomes so a failed provider start does not erase successful sibling reservations. The provider exposes no atomic compare-and-stop relative to independent native clients.

For a pinned Go owner, the caller recognizes the original Claude external-resume implementation via the owner-only context-guard read. It acquires already-settled sessions. A Go owner or prior Rust owner cannot reserve a live batch through this protocol, so the new caller refuses before stopping any native session.

The Linux capacity witness used two live installed Claude 2.1.329 sources and 63 independent live Swarm reservations. Takeover refused and both native sources stayed live. With exactly two available slots, the fixture held the native stop open and submitted a competing launch. The competing launch got the session-limit refusal, and both Claude sources acquired the two reserved slots. The external Rust and Go fixtures also passed, including duplicate identity, changing inventory, and previous-owner refusals. The actual pinned Go owner left the source running when asked to take over and acquired it after an independent native stop. All fixture cleanup reported no survivors.
