# Rust Codex owner history

The owner `interaction_history` wire accepts a page size and an optional `before_item` anchor. Each retained interaction carries a stable `item_id`. A cursor outside the retained window returns an empty page at the history floor. Pilot view and watch use the same durable owner journal and treat native content as worker data.

The private backend observes completed user and final assistant messages for the exact ordinary Codex thread and turn. The first reply can finish before the observer joins. On join, a bounded opening backfill reads the exact authenticated rollout and requires matching native root-turn, thread, item completion and final text evidence. The journal retains plain text up to 4096 bytes per item. Existing rollout history for a viewer newly resumed from another row, unsupported message types, and messages outside retained bounds are unavailable through this journal.

The owner wire paged from the reply back to the original prompt, safely handled a forged anchor, and Pilot viewed and replayed the same reply from the user-message cursor. No fixture processes survived. macOS Clippy and journal unit tests passed.

The operator surface follows the pinned client dispatch. Codex approval and question replies remain in its native terminal. The retained owner history wire serves Pilot, and the top-level CLI keeps its existing verbs.
