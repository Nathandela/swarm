# Ordinary native Codex origin

An ordinary Codex owner launch can use an explicit, physical `CODEX_HOME` below the caller's physical HOME. The native home must be owner-only and its config and authentication files must be owner-controlled regular files. The supervisor rejects aliases and the retired Swarm login-store paths. It carries the admitted native home through ordinary and reliable launch. The shim verifies the reserved device and inode before exec. Resume requires the same native home, account, config, checkout and exact rollout. Unsupported profile names, authentication selectors and endpoint environment overrides continue to fail closed.

On 2026-11-26, installed Codex 0.172.0 on Linux x86-64 passed `parity_codex.py --native --loopback-model --resume-check --alternate-check`. The fixture verified a separate native home, exact reliable launch replay, refusal of an alias and retired account path, and refusal after swapping to the default origin or changing the alternate profile's synthetic account. Resume rendered the old reply without opening a new user turn. Cleanup reported zero survivors. macOS Clippy and four Codex tests passed.

The installed macOS 0.172.0 candidate exited with EPERM before publishing its private app-server socket under the scratch-only fixture guard. The pinned provider creates the real socket and startup lock in `/private/tmp/codex-daemon-<euid>` even when HOME and CODEX_HOME are disposable. A read-only search found no dedicated local fixture UID. Installed Mac native qualification requires an isolated test UID or host with its own vendor socket namespace.
