# Rust Codex resume verification

The owner accepts `launch.options.resume_from` for a stopped ordinary managed Codex viewer. It verifies the original account and physical native profile, checkout, configuration, exact rollout header and native thread. The shim rechecks the source before starting the private app-server and verifies a native `thread/resume` response for the exact idle thread before starting the viewer. The resumed row records `resumed_from`. A second live or unconfirmed writer for that thread blocks another resume.

Run the disposable Linux fixture with `scripts/verification/parity_codex.py --candidate <swarm> --provider <codex> --native --loopback-model --resume-check`. The fixture uses its own HOME inside a private namespace and a loopback Responses server. It sends one real Codex turn, restarts the owner, stops the source, checks that changed config blocks resume, and verifies that the viewer presents the old reply without starting a second user turn. It then checks that another viewer cannot resume the same thread while the replacement owns it.

The qualified origin is the ordinary physical `HOME/.codex` profile. Config comparison is fail-closed on any change, including preference rewrites. The fixture seeds the vendor's screen-reader and model onboarding preferences to keep the profile stable during the test. Explicit profile and alternate origins, approval and question replies, structured interrupt, and owner-visible history are separate qualification work.

On 2026-11-26 the fixture passed with installed Codex 0.172.0 on Linux x86-64. The retained original rollout still recorded exactly one `task_started` event after resume. The real provider also emitted an ephemeral title-generator thread. The observer ignores only events explicitly identified as ephemeral title generation.

The Linux fixture also mounts a private writable policy directory at the vendor's system path inside the namespace. Each of `config.toml`, `requirements.toml`, and legacy `managed_config.toml` blocks owner reservation. Adding requirements after reservation also blocks the real resumed shim before it opens a native worker. The no-policy case still resumes through installed 0.172.0. The macOS implementation checks the vendor's forced `com.openai.codex` values using CoreFoundation and refuses a forced setting or failed synchronization. macOS build and lint passed. An installed macOS resume witness and a managed cloud policy witness remain open. The keyboard-driven board now exposes ordinary stopped Codex resume. The installed Linux fixture focused the stopped source on a real terminal, pressed `r`, observed the new row's `resumed_from` lineage, and saw the native Codex viewer auto-attach. The native snapshot contained the prior reply and the source rollout still recorded one user turn.

## Hands-off from a live Codex session

An installed Codex 0.172.0 on Linux x86_64 produced a native rollout and answered one loopback request. With that viewer running, the owner launched a Claude fixture as its successor. The executable received the original transcript path, native conversation UUID and checkout from the owner. A caller-supplied opening prompt was discarded. The source remained available until the fixture killed it independently. The existing resume witness subsequently reopened the exact native rollout and observed one original user turn. The final cleanup reported zero survivors.

The owner verifies the source instance, effective checkout, active account, native profile, policy, configuration, thread and rollout inode. The successor shim repeats those checks immediately before executing the provider. It takes the source account environment from the original supervisor's private saved state. Dated-rollout regressions cover a UUID minted before midnight whose transcript appeared in the following UTC day, and refusal when two candidate days contain the same UUID. Resumed and externally acquired sessions also verify their original rollout path and inode. Replacing that file with a copy bearing the same header is refused. The native witness runs as part of `parity_codex.py --native --loopback-model --resume-check`. Claude was a local receiving fixture in this handoff run.
