# Retained Go Discord state

The retained-state witness uses original Go personal and teammate configurations and their bbolt stores, built by Go at f26648d69086e329132ac7849954d2f29a895387. The fixtures include persisted audience exclusions, a settled Go delivery with exact replay indexes, and uncertain delivery and ingress cases. A synthetic credential stays in its original file and the test makes no Discord calls.

`swarm discord migrate-state --dry-run --state-dir DIR` inventories supported private Go evidence without opening the ledger writable. For a qualified disabled installation, the command without dry-run commits a dormant retention record bound to the exact installation, directory, config and database digest. `--rollback` marks the transition rolled back without rewriting the original Go config, database or credential. Rust grants neither Gateway nor VM project authority. A writer lock, unresolved effect, unknown ledger data or changed source leaves authority with Go.

`swarm discord migrate-supervisor --dry-run --state-dir DIR` checks both live owner namespaces and the original connector selector. It binds the original Go socket peer to its kernel birth record and verifies the destination Rust peer executable. The configured lock must belong to the socket peer, on both the original and destination supervisors. Linux checks the peer's file descriptor lock record. macOS requires an exclusive whole-file lock and refuses ambiguous file holders. The witness substitutes a private but unrelated held lock in each place and checks that migration leaves config and selection untouched. For an original Go connector, the apply command updates Go-readable home and prior-owner coordinates while leaving the connector database and earlier selector in place. Go retains its earlier routing for previously bound discussions. The witness persists a teammate discussion through the original Go binding transaction before the move. After the move, the pinned Go runtime resolves that same discussion to the original owner, and a newly bound discussion to the new owner. Both sockets report their respective running synthetic agent sessions throughout. The pinned Go ledger still reads the same completed and uncertain delivery outcomes. If config publication finishes before the new selector is written, the same command completes selection on retry. Connector runtime startup and existing Rust Inbox migration require separate qualification.

`swarm discord migrate-state --controls --dry-run` reports whether a selected, enabled but stopped original place can use Rust audience controls. Apply with `--controls` and use normal `swarm discord exclude TARGET` and `swarm discord include TARGET` while the connector is stopped. Rust verifies the original supervisor roster and writes only the exact Go `optouts` bucket in a bbolt transaction. The receipt includes the private database and directory identity, unchanged enrollment and a digest of the remaining ledger. Known uncertain request records are retained byte-for-byte. Unsupported active linkage, an occupied bridge, an unknown target or changed delivery evidence leaves the database untouched. `--controls --rollback` revokes Rust audience mutation access. The pinned Go store then sees the exact values committed by Rust and can continue updating them. This scope leaves Gateway and native manager execution with the original implementation.
