# Live Go classic agy owner round trip

With both Go compatibility flags enabled, the Rust owner can adopt an ordinary classic agy terminal running under the pinned Go wire-v2 shim. Classic agy has no managed native-writer record. Admission checks the original private shim and hook socket peers and authenticates the same start time. It finds a unique controlling-terminal session leader among the actual children of that shim and captures the worker's kernel birth identity. It accepts the pinned Go default status-line envelope, which newer agy releases receive as their first CLI option. Managed native side files or unfamiliar settings cause refusal.

The official agy 1.5.17 executable completed a Go → Rust → Go round trip on Linux x86-64 and macOS arm64. Each owner produced a distinct native request and assistant turn in the same transcript with the same process and PTY. The original Go owner recorded the original conversation ID after graceful terminal exit. A forged managed writer file blocked Rust adoption without changing either process. The established Go shim retains its own terminal lease arbitration and hook spool across both owner replacements.

Run `python3 -Bu scripts/verification/live_go_agy.py PINNED_GO RUST AGY SCRATCH` with a fresh private scratch root. The test checks its macOS write and network sandbox or requires a whole-fixture Linux sandbox with an isolated PID and network namespace. It runs the vendor binary against a loopback Gemini fixture with generated configuration and no installed credentials.

This covers classic terminal custody and native history continuity. Structured ACP, custom Go status-line command chains, and other managed or scheduled agy scopes need their own qualification.

## Can live adoption qualify a later stopped resume?

A guarded Go launch with official agy 1.5.17 and a synthetic Gemini endpoint was inspected on macOS 27.2.1 arm64 and Linux x86-64. While the PTY was active, the kernel reported the vendor executable and checkout with the expected device and inode. The shim and worker had distinct birth identities and the expected parent and process-group relationship. macOS reported the executable and checkout through `lsof` and birth through `PROC_PIDTBSDINFO`. Linux reported them through `/proc`. The file mapping observations included `dyld` on macOS and the dynamic loader and system libraries on Linux. This sampled the live image and some file-backed dependencies, with no complete dependency attestation. The physical scratch home and the transcript in the native UUID directory also had distinct, observable device and inode identities before graceful stop.

A scratch-only extension of the default Go status-line chain saved the vendor process's raw status JSON after a completed model turn. The payload agreed with the native transcript UUID and Linux and macOS process checkout. Its `cwd`, `workspace.current_dir`, and `workspace.project_dir` all identified the checkout. On both hosts, the advertised `transcript_path` used `.gemini/antigravity/brain` and was absent on disk. The real transcript in `.gemini/antigravity-cli/brain` contained the original turn under the matching UUID. A proof would need to open the actual transcript and bind its inode. The Go hook retains state, title, and conversation ID, so its durable output also loses the raw workspace fields. [Pinned Go status-line hook](https://github.com/Nathandela/swarm/blob/f26648d69086e329132ac7849954d2f29a895387/cmd/swarm/agy_statusline_hook.go)

The raw status on both hosts exposed no auth method or account identity. The native startup log reported the method `gemini_api_key` with empty email and quota project fields. The Linux kernel exposed the presence of the fixture wrapper's Gemini key and endpoint environment names. Those are process inputs and the fixture's loopback server is operator-controlled. Neither identifies the principal selected by the provider. The command-line help offered remote-control daemon status, with no account query for the classic worker. The probe used no user credentials, and OAuth account selection remains unqualified. Even a fresh capture of physical home, checkout, image, process birth and transcript would leave same-account stopped resume unproved in this scope.
