## Defects found by the spikes

The optional Codex updater could block thread creation. The manager invocation now suppresses that prompt without changing the user's global CLI settings. The required MCP subprocess also needs the daemon-issued `SWARM_SESSION_ID` passed explicitly in its environment. A pending native custody write previously made the status check refuse a legitimate in-flight call. The corrected check waits within the caller's deadline and still compares all native identities and argument hashes.

Worker creation initially sent zero terminal dimensions, which the daemon refused before reservation. A second run created the worker but failed to settle its receipt. The owner protocol returns a **namespaced** session ID. The controller now verifies the reported endpoint and exact roster incarnation. The hosted restart test passed after correcting both issues. The previous controller's v2 bbolt ledger was tested using a fixture generated by the previous writer. Migration checks digests and preserves admission floors, uncertain actions, historical receipts and the existing native conversation.

## Private service and device authority

The test suites exercise the Unix owner control and separate manager MCP sockets, durable launch intent, observer readiness, stale binding rejection, single launch after lost acknowledgements, recovery-only access after custody loss, exact owner replacement and no unrelated worker stops. Native proof retention preserves old interrupt dispositions and refuses missing manager startup identity. Both controller and device clients enforce byte and time bounds.

The device fixture runs a real SSH direct-tcpip channel to a loopback HTTP service. It uses independent SSH and Ed25519 signing keys. Tests cover single-use enrollment, signature/body binding, per-device receipt isolation, reconnect, paging, changed audio, and revocation while transcription is blocked. Revocation finished before the transcription returned and the returned text never reached the manager. The standalone SSH cancellation fixture woke blocked readers and writers within 2.3 ms of cancellation over three local runs. This measures local cancellation, not network latency.

## Android and outstanding gates

The app exposes opt-in setup and explicit recording, protected device-grant storage and a user-started microphone foreground service. The mobile API and Android gate tests ran against a Go-built AAR. Kotlin/Robolectric tested setup and service lifecycle. The Android setup requirements, supported controls and physical-device limits are in the [handset guide](../../../android/voice-device.md).

The host currently has Apple Command Line Tools without a full iOS SDK. Signed iPhone builds, real lock-screen recording, interruptions, acoustic latency and the multi-hour soak still require their target environments. A physical Android handset was absent during the initial inventory. The owner requested removal of the temporary OpenAI staging file only after the entire manager ships.


## Scheduler cost

An idle controller originally deep-copied its ledger twice a second. The store already performs copy-on-write publication of committed tables. Internal scheduler reads now borrow those immutable tables. External snapshots remain detached copies. A race test checks that a reader holding the previous committed state can see neither the next capture update nor a partially applied transaction.

The existing `BenchmarkControllerIdleTick` was run on the same Apple M1 with two ten-iteration samples at each load. At 10,000 records the baseline allocated about 3.08 MB and 30,120 objects per tick. After the change it allocated about 7.5 KB and 82 objects. Baseline wall time was 2.8–3.3 ms per tick and the new samples measured 0.20–0.23 ms. These are local fixture measurements, independent of provider latency.


## Follow-up controls

The owner can inspect a specific active manager turn and request interruption using its saved binding, input and native turn IDs. The deterministic operation survives a lost reply. A generic native acknowledgement stays pending until retained terminal evidence confirms interruption of that turn. Ordinary worker interrupt capability still depends on an adapter offering an exact, durable owner operation.

Signed device status uses a device-scoped replay stream. Resume validates the version and cursor, and a gap returns a scoped snapshot. The microphone lease admits one capture across devices. Focused tests covered explicit takeover while transcription was running, revocation, End, conflicting audio, and same-ID receipt recovery. They also exercised signed per-device playback authorization on the real loopback SSH transport with a fixture provider. Clip bytes, playback-head progress, and a human hearing intelligible speech are three separate observations.

The Android app includes explicit Read aloud and local Stop. The preview targets an exact publication, uses mono 24 kHz AudioTrack output and observes focus, route, binding and activity changes. It exposes playback-head progress. Both Kotlin and Go fixture tests were used. The initial inventory found no attached handset and no installed emulator system image.


## Apple component and remaining release work

The Apple package builds on macOS with Swift 5.10. Its checks exercised separate CryptoKit signers and profile/grant behavior. The Swift client bridge typechecked against Objective-C headers generated from the actual gomobile facade. The XCFramework preflight reported missing Xcode, iPhoneOS and iPhoneSimulator SDKs. A signed iOS application, physical lock-screen audio and distribution remain open. [Apple build and custody notes](../../../ios/README.md)

The scope of this integration is explicit push-to-talk and user-requested playback. Continuous duplex manager delegation, physically measured interruption and latency, comparison of identifier fidelity, both native accounts on every route, and the release soak remain qualification or implementation work. The standalone GPT-Live conversation command still has its own speech-only semantics.

## Candidate verification

The final code checkpoint is `5f6d0100`. Go 1.26.10 on Apple Silicon built the repository, and vet and golangci-lint passed. The production reachability gate now passes without exemptions for the previously disconnected controller, wire or interrupt functions. The full Go suite passed with `-timeout 30m`, and the full race suite passed with `-race -timeout 35m`. Both reported 90 passing packages and eight packages without tests. The long supervisor package exceeds the default ten-minute budget on this machine.

The source-exact Android AAR included arm64-v8a and x86_64, with SHA-256 `1538fb3da8a603fea4deb39062846e0e90a0012006809d7a065086123567c3d7`. Its checksum was unchanged before and after Gradle. All 1,737 JVM/Robolectric tests passed, with no failures, errors or skips. The debug APK SHA-256 was `6caa03fff2559e7c1aa96c50ebe0b0c9be41734be8f4723a55bb1abbf129e54f`. An earlier verification run read an old AAR while a rebuild was in progress. The final sequence built the AAR before allowing the artifact checks to start.

To reproduce the hosted checks with the development binary, use `scripts/verification/voice_manager_turn.py <binary> codex` for a read-only roster turn. Add `--worker` for an isolated worker launch and exact retry. The mutually exclusive `--speech-key-file <private-file>` mode streams a fixed phrase synthesized on macOS through the real manager and requests a bounded spoken preview. Both paid providers use the intended native account or configured speech project. The harness uses its own state, cleans up its created sessions and removes its disposable speech credential copy.
