# Native manager implementation qualification

On 2026-11-08 the production Claude manager sender, guard and private broker passed an isolated fixture using installed Claude Code 2.1.319 (binary SHA-256 in [native-implementation.json](native-implementation.json)). The fixture copies the executable, registers it with the standard test supervisor, uses a fresh private HOME/configuration and synthetic account/model, confines network traffic to loopback, and cleans up the exact owned native/MCP processes. It uses no real credentials, microphone, production sessions or provider calls. `SWARM_NATIVE_MANAGER_PROOF=1 go test ./internal/claudeinput -run '^TestNativeClaudeManagerProvenance$' -count=1 -v` passed in 16.54 seconds using the cached ARM Go 1.26.10 toolchain and shared caches, with all six inherited Swarm session variables unset.

The production chain binds a registered one-use input nonce to the unique invocation plugin origin, the final stored user message UUID/projection, the exact main native turn, the native streamed tool ID and arguments, and the MCP host `claudecode/toolUseId`. The model's deliberately false `turn_id` argument did not become authority. Installed 2.1.319 shortens the plugin display name to 23 ASCII characters plus an ellipsis in its stored wrapper; source authentication continues to compare the full unique origin name. A regression captures that observed wrapper, rather than accepting approximate matching.

The fixture demonstrated explicit startup readiness; false readiness while a model/tool turn runs; completion followed by a native awaited continuation; exact abort followed by a fresh input; false readiness while a real native tool permission modal remains open beyond the broker's three-second liveness horizon, no MCP host call after its cancellation, and recovery to explicit idle; native model error and refusal followed by fresh inputs; same-running-turn manual TUI steering; proof refusal after that steering; and historical completion retaining the original nonce/turn with `externally_steered:true`. Canceling a native tool expires its hook context, so the guard closes its call locally immediately and publishes its bounded completion tombstone from a fresh native lifecycle/timer context before turn completion or subsequent tool attestation. The deterministic canceled-hook regression first failed, then passed with this change. The fixture's MCP peer invokes the broker resolver while the real native call is pending. It does not inject a registry proof or substitute a terminal screenshot for native events.

Common registry tests cover child and direct-terminal refusal, mismatched arguments, precise canonical JSON numbers, native call completion/replay, changed generation/account binding, cancellable bounded race waits, explicit idle separate from completion, delayed RPC receipts, immutable external-input baselines, and completion arriving before the first start observation. Unknown completions now retain bounded closed-turn tombstones; if capacity prevents retaining closure, the registry retires instead of forgetting the closure. The independent Codex completion-before-start overlay and permanent regression passed with the race detector.

The owner-only protocol now exposes `manager_runtime`, `manager_resolve_call` and `manager_input_status` under negotiated `manager-provenance`. Status includes explicit readiness and server-derived private bridge references. Physical native generation and authenticated observation generation are separate required binding coordinates. Codex observer redial/restart changes the observation epoch; Claude retains its broker/guard epoch across daemon restart while the broker remains alive. A changed full binding requires explicit reconciliation. Historical nonce outcome lookup neither submits input nor reconstructs native permissions after observer loss. The owner roster's optional `native_owner_input` is a retained hint independent of OpenCode's `native_composer`; actual semantic send still revalidates its native sink. [Owner hint performance qualification](owner-input-hint.md) records the bounded asynchronous refresh and shared-fanout latency regression. Unsupported or unenrolled sessions do not gain raw-input fallback through this hint.

This is focused implementation evidence, not a production/soak close. Codex production observation and send qualification is recorded separately by its owner; the earlier actual installed Codex 0.167 causal probe remains in [native-provenance.md](native-provenance.md). Lost Codex feeds do not reconstruct registry authority from durable receipts. The Claude broker currently retains at most 128 manager input operations without eviction; the shared registry has a combined 1024-record cap and safely refuses new evidence or retires on an unrecordable closure. Both limits need acknowledged settlement and replay-safe capacity recovery; durable settlement-aware retirement is still required before claiming an eight-hour persistent-manager soak. Full controller/MCP bridge integration, general owner interrupt/resume guards and independent review remain separate gates. No blanket adjacent-version allowlist was added.
