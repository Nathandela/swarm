# Native manager provenance — 2026-11-08

Both installed managers expose a practical causal publication path. No model-supplied turn ID, natural-language text match, MCP JSON-RPC request ID, or current-turn guess is needed. This investigation changed no production code. [Sanitized evidence](native-provenance.json) records exact native executable hashes and observed joins. [Experimental probe sources](probes/README.md) reproduce the isolated checks; the tiny MCP recorder is not a production server implementation.

Claude Code 2.1.319 was run as its actual interactive TUI, using the production native-input broker/mods, a separate experimental observer, synthetic credentials, and a loopback fake model. The whole-chain probe passed in 12.28 seconds; the busy-queue probe passed in 12.38 seconds. A copied Codex 0.167.0 app-server was run with its own private synthetic configuration, fake Responses endpoint and stdio MCP recorder. OS guards restricted writes to scratch and network to the fixture. No production sessions, real credentials, paid model calls or microphones were used.

## Observed joins and exact integration points

**Claude input admission:** persist an opaque, random, one-use control nonce with the service admission, exact human text digest and immutable manager/native generation before native submission. Only the owned sender plugin may introduce its envelope. The probe rejects reserved envelopes from composer/other origins and repeated plugin envelopes; this is an explicit machine protocol, not matching ordinary human text. A production manager should use a unique per-launch sender identity and keep this behavior scoped to opted-in managers.

Observe `prompt.submit`'s engine-pinned plugin origin. Then observe the final `session.append` result for a main-loop prompt: its pinned origin, `door`, `uuid`, and final stored content. Claude wraps plugin text before `turn.start`; the submitted text is therefore not the turn text. On main `turn.start`, resolve the single pending nonce through that attested append, verify its exact native projection, consume it once, and bind the service admission to `turnId`. Missing, altered, merged, repeated or ambiguous proof must pause automatic dispatch rather than infer ownership. Keep the human transcript/digest separate from the native envelope/projection digest.

**Claude tool provenance:** `turn.step` has pinned `turnId` and `agentId`; its streaming `kind: "tool"` chunk names the exact tool-use ID. Record that join before yielding the chunk. At `tool.call`, validate the pinned `tool_use_id`, `agentId`, tool name and final canonical arguments and send an authenticated sideband attestation before invoking `next`. Actual stdio MCP `tools/call` carries `_meta["claudecode/toolUseId"]`, matching both native events. It did not carry agent or turn identity directly, including for the real child call. The MCP bridge joins that host metadata to the sideband; it must not trust a `turn_id` argument. The probe demonstrated that a hook can overwrite an argument, but production needs no authority argument or `hook_stamp` field.

Add these narrowly to `internal/claudeinput/guard.js` and the broker runtime seam: register native admission; register exact native call proof; read/consume proof by manager generation and tool-use ID. Fail closed on missing/stale proofs, hook failures or ID collisions. Child calls retain their own `agentId` and must not inherit the manager's admission, even when their prompt contains the same nonce. Unrestricted native tools can still run; this is bridge provenance, not an OS sandbox for the agent.

**Codex input and tool provenance:** retain the existing shim-owned app-server/TUI thread and native `turn/start` or `turn/steer` receipt. Actual 0.167.0 MCP `_meta.callId` equalled `item/started`'s `mcpToolCall.id`. `_meta.threadId`, `_meta.sessionId` and `x-codex-turn-metadata.turn_id` matched the native frames. Server, tool and complete arguments matched as well. `_meta.itemId` was a different Responses item ID and must not be used for this join. The model's deliberately false `turn_id` remained in arguments and granted nothing.

Extend the exact-instance backend observation path in `internal/skeleton/backend*` to retain `mcpToolCall` start/completion coordinates for `swarm_voice` before the generic interaction projection discards unsupported item types. Join MCP metadata to the trusted native item, thread, turn, server, tool and canonical arguments. Bound any wait for ordering between the native-event and MCP channels; hold no backend-reader/store lock while waiting. Refuse foreign/child threads and unknown or conflicting calls. No dynamic-tool owner, second app-server or shadow `thread/start` is required. The isolated probe owned its own thread solely to test the native protocol; real Swarm thread adoption remains an integration gate.

## Shared service contract

The private MCP process credential and inherited session ID identify the manager instance, not its turn. Resolve each tool call's native proof server-side, then obtain the durable service admission. Keep transport call IDs separate from logical action/publication IDs: exact business requests must remain retry-stable when native/MCP request IDs change. Strip any experimental transport stamp before computing business payload hashes.

Before every effect, revalidate controller/manager generation, native admission, task/request lifetime, immutable target and exact payload; persist the original action/receipt namespace first. Speech permits remain bound to the proven native turn. Stop revokes that producer permit, and later calls from the same running turn stay text-only. Native turn completion, input admission, publication, actual playback and task success remain distinct facts. A model acknowledgement can be useful UI evidence but grants no causal authority.

The busy-queue test submitted the nonce while an initial model turn was blocked and also typed ordinary composer input. The composer input was attributed to the old native turn; the plugin envelope later received its own main turn. An identical composer envelope and a repeated plugin envelope were refused. A real native child received the same nonce but stayed unbound. `/clear` retired the experimental generation. Queued-input cancellation was not proven: already-admitted work must still be reconciled and must not be described as cancelled merely because playback or the current turn stopped.

Remaining integration checks are durable nonce/proof recovery, late MCP arrival after clear/stop, hook failure, duplicate native tool-use IDs, altered/merged envelopes, request/argument conflicts, actual shim-owned Codex adoption and supported third-party mod ordering. No stronger guarantee against hostile same-UID processes or arbitrary native plugins is claimed. The observed native APIs remove the earlier causal-seam blocker; they do not complete P3/P4 or release qualification.
