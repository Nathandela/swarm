# Owner native-input hint performance qualification

On 2026-11-08 independent review found that owner roster projection synchronously queried the Claude broker from `Server.distribute`, which is the shared status-event drain. A real stalled private Unix HTTP broker made a single native-input hint wait 152.39175ms; 64 stalled workers could multiply that delay during List. The permanent stalled-broker and no-subscriber fanout regressions failed before this change. The original independent overlay is also retained in the verification run.

Roster projection now uses only a retained in-memory capability snapshot through `OwnerSessionCapabilitySource`. Exactly one daemon worker performs refreshes outside fanout. Its queue has 64 slots plus at most one active refresh, and its replaceable hint table has 256 entries. A true hint expires within one second; native Claude probing has a 150ms deadline derived from daemon cancellation. Cold, expired or saturated qualification stays temporarily unavailable. The actual semantic send still revalidates the native sink, and cache eviction removes no operation/admission guards.

Snapshots bind both the capability session instance and current shim PID/start tuple. Capability replacement/session end invalidate queued and active refresh tokens; late responses cannot republish retired snapshots. Daemon shutdown clears hints and cancels a hung refresh before joining its single worker. Ended short-lived workers can still publish their original validated immutable session instance with `native_owner_input:false`, allowing launch-result reconciliation without granting input readiness.

The exact independent overlay and permanent regressions pass with the race detector. The measured lookup/fanout results and resource bounds are in [owner-input-hint.json](owner-input-hint.json); times are observations under the test host's load, not universal latency promises. Tests cover the actual private Unix stalled broker, no-subscriber event fanout, 512 cold reads, queue limits, shutdown cancellation, revocation refresh, physical replacement, stale base-instance refusal, ended-worker identity and late successful-response invalidation. Existing ordinary Claude owner/native routes also remain green.

The changed source is limited to owner capability projection/refresh; the installed 319 native guard/turn qualification remains unchanged. This does not close the separate Claude 128-admission/common 1024-proof-record retirement gate or claim an eight-hour production soak.
